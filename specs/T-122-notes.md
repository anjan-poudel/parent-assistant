## Deliverable 1 — the pinned-surface guard (technique and coverage)

`ios/ElderlyAssistantTests/Services/Voice/PinnedSurfaceGuardTests.swift` — a NEW file; both pinned
suites (`GoldenCorpusTests`, `IntentPromptTests`) are untouched, and the `>= 15` floor remains
`GoldenCorpusTests`' own (mirrored, never replaced).

**Golden-corpus block pin (source-byte technique).** The guard reads
`GoldenCorpus.swift` from source at test time via `#filePath` (`FeatureSourceScan.iosDirectory`,
the app-launcher / Spotify-auth source-plist convention), extracts the `// MARK: - music` region —
the marker line (actual: 140) through the array's closing `]` line (actual: 158), verbatim — and
checks, in order:

- entry count: exactly **15** `.init(..., intent: "music")` rows (14/16 fails);
- block sha256: **`fb14012e836a33a3d889ae0610db44ebd3ea1f9b747aa0e368cc38a7221296e2`**
  (any byte change in the region fails, including the `static let music` declaration line and
  framing/comment inserts; recorded for reference: an entries-only slice would hash
  `6155deecd187b19eecaaf10422033d62db9cbb1cccd06f1e0fef06d74a54db1d` — the guard deliberately
  pins the fuller marker-to-bracket region);
- every entry row still carries `intent: "music"`;
- every failure message contains the literal surface name **"GoldenCorpus.swift music block"**.

**Floor-test presence pin.** The guard reads `GoldenCorpusTests.swift` (read, never edited) and
fails if `func testCorpusHasAtLeast15EntriesPerIntent()` or its
`XCTAssertGreaterThanOrEqual(count, 15…` assertion is deleted or weakened — a green floor run can
never be vacuous. This is an addition beyond the letter of the task (documented under deviations).

**Prompt tripwire pins (independent copies).** The guard recomposes the exact `IntentPrompt.build`
compositions `IntentPromptTests` pins, using fixture values copied from that file, and compares
against **its own literal copies** of the digests so it keeps enforcing them even if
`IntentPromptTests` is weakened or deleted. Coverage (as listed in the guard's coverage comment):

|---|---|
| `IntentPromptTests.defaultNoTermDigest` | sha256 `18003dddc2a0c16d6fab3be7ffb0f2d93802e1a161f54e05e98a7f33f24b8b78` (build, `"test transcript"`, meds `[]`, hint `ne`) |
| `IntentPromptTests.weatherNoTermDigest` | sha256 `bd47910d74d5c10d2ad889e1bb9a6f1e6093b59bb8fb7f03bb765f8f016e00ff` (build, `"भोलिको मौसम कस्तो छ?"`, meds `[]`, hint `ne`) |

Recomposition is byte-exact through the public (`internal`, `@testable`) API, so no fallback
limitation applies; the guard comment states the technique. Failure messages name the surface
("IntentPrompt.build composed bytes" with the fixture named).

**Scenario 3 automated.** `testTheMusicBlockPinFailsAndNamesTheSurfaceOnAnyMutation` exercises the
pure predicate over synthetic in-memory copies of the real source: one entry byte-changed, a
sixteenth entry added, an entry removed, and the anchor removed — each must produce a failure whose
message contains "GoldenCorpus.swift music block". Deliberately no on-disk mutation is performed
(the pinned files are off-limits, and a parallel agent works in this worktree).
