## Summary

**SECURITY-GO.** The design carries a real security architecture for all six mandated surfaces plus the FR-PI-016 routing amendment. The single profile string that can enter a prompt is pulled through one read seam (`addressAsForPrompt`), guarded with the shared InputSanitiser discipline, composed only inside the quoted slot of a fixed static clause, and bounded to 24 graphemes. The whole-record store keeps all five fields on the encrypted-file channel with explicit absent-vs-unreadable discrimination and whole-record decode, so no partial value can be read. The log surface is content-free by construction, with fail-closed runtime choking (redaction before the allow-list) plus a build-blocking source gate over the feature's own files. Egress grows only by that one term riding the existing consent-gated prompt paths; the name is deliberately excluded. The voice-fingerprint step is a call site over the unchanged mechanism. Every failure mode in the personalization, the wake ack, the store, and the app-start routing degrades to the un-personalized baseline with defined routes, no fabrication, and no retry loops.

**No blocking finding was identified.** Seven findings (SD-1 … SD-7) are recorded; none requires an architecture change; four are routed as design-text amendments and the rest as implementation or evidence items. The most consequential is **SD-1**: the guard's protection against instruction-shaped input is bounded by the shared marker table's English/transliterated phrase list — the requirement's own example (`ignore your instructions …`) matches no table entry and therefore reaches the prompt as quoted data. The safe-outcome claim for such inputs rests on the quoted-slot framing, the clause wording, and the absent capability (no action, no profile write, routing and output validation unchanged) — a sound basis, but it must be stated explicitly in the design and evidenced by `security-test`, whose plan must exercise in-table and out-of-table payloads separately.

**Assessment counts.** 6 required surfaces and 36 threat rows assessed; 0 blocking findings; 4 design-text amendments; 10 evidence obligations for `security-test`; 3 residual risks named for owner acceptance/reference (OD-PI-5, the disclosure window, and the existing biometric threat model).

## Assets, trust boundaries and data flows

| Asset | Where it lives | Sensitivity |
|---|---|---|
| Name, address-as term, DOB, GP, hospital | encrypted-file store, key `user.profile` | PII; the term additionally enters the prompt paths |
| Next of kin | existing `family.contacts` flag (`isEmergencyContact`) | PII; existing protection unchanged |
| Family contacts | existing `family.contacts` store | unchanged |
| Voice fingerprint | existing Secure Enclave-backed store | biometric; unchanged |
| Interview status | `UserDefaults` step map + profile snapshot | low; drives routing only |
| The composed prompt (cloud + on-device) | in memory per turn | contains exactly one profile value: the guarded term |
| Log surface | `LogSanitiser` choke point, console, telemetry | must never carry any value from the rows in this table |

Trust boundaries are L1 §7.1, unchanged: **B1** user entry (trim + grapheme bound only; adversarial content expected and neutralised at composition), **B2** the encrypted store (readable only with the app's key material, device unlocked), **B3** egress (only the guarded term may enter the existing prompt paths under the existing consent). This review adds **B4**: the log boundary — every event passes `LogSanitiser`; the source gate is the build-time backstop.

## STRIDE threat model

### Surface 1 — User-entered profile strings reaching the shared prompt (NFR-PI-004, FR-PI-009, FR-PI-010; injection)

Data flow: entry (C03, clamp 24) → store → `ProfilePersonalization.addressAsForPrompt` (C07) → `guarded(_:)` → `InterpreterContext.addressAs` → `addressAsClause` (C06, §5.5) → `build` / `buildChat` / `buildUnderstanding` → on-device LLaMA and cloud Gemini.

- **S — spoofing (role re-assignment).** A term imitating system/role text (`system:`, role markers, instruction verbs) tries to re-role the model. Mitigation: `guarded(_:)` runs `InputSanitiser.sanitise(.quarantine)` (control-strip, whitespace collapse, marker removal — 12 English/transliterated entries, single-sourced) then strip-then-detect via `containsInjectionMarker` and returns nil to any residual marker shape, so the turn runs un-personalized (C07, §5.3, §9.3). Residual: the marker list is phrase-based and English/transliterated only, so non-English (including Devanagari) or novel-phrasing instruction shapes pass into the quoted slot; containment there is the data framing plus the absent capability (SD-1). Grade: mitigated with a named evidence obligation.
- **T — tampering (clause break-out).** A term tries to close the quoted slot and inject new reply-style rules or reach the emergency-classification guidance. Mitigations: whitespace collapse removes newlines; quote-slot neutralisation replaces `"` with `'`; the 24-grapheme clamp bounds the payload; the clause is a fixed static string appended at three exact anchors; the seed mirror gate pins template bytes (§5.5, §9.2, §9.3). Residual: the Unicode quote family and the backtick are not neutralised (SD-2); a semantic attempt inside the slot is contained by the clause framing and the model's treatment of quoted data, not by escaping. Grade: mitigated.
- **R — repudiation.** A helping family member enters or changes the term; no attribution or audit trail records who. This is surface 2's accepted item (SD-6; owner-resolved OD-PI-5). Grade: accepted by owner.
- **I — information disclosure.** Injection attempts themselves become prompt content; guard rejections are content-free events (`profile_prompt_text_quarantined`, no metadata, §5.3, §7.3). No leak beyond the term disclosure already inherent to the feature (surface 4). Grade: fine.
- **D — denial of service.** An oversized or pathological term tries to blow the on-device context or loop the guard. Mitigations: quarantine clamps to 200, the guard clamps to 24 graphemes on `Character` boundaries, the composition bound equals the entry bound (no stored term is ever truncated at composition), the pinned 3,000-character ceiling holds at worst case 2,586 (headroom 414; ≤ ~20 tokens), the guard is O(term ≤ 200), and no path retries a rejected term (§9.1, §9.3, §12). Grade: mitigated.
- **E — elevation of privilege.** A crafted term tries to cause a tool action, an intent-routing change, or any profile write. Mitigations (structural): the term enters reply-style guidance only, as quoted data; no capability is attached to prompt text; model output remains untrusted through the unchanged parse / confidence / sanity gates; profile writes exist only on the UI writer path (C01 single writer, §5.6); the name is excluded from prompts entirely (ADR-07), shrinking the surface to one string; both context sites pass the same guarded accessor (§5.5). Residual: model-level compliance with an out-of-table payload is not provable on paper — hence SD-1's evidence obligations (replay assertion: routing for a fixed utterance is unchanged with a hostile term present; no action triggers; no write). Grade: mitigated with evidence owed.

**Seed-mirror and prompt-budget interplay (reviewed).** The seed gains `{address_as_clause}` defaulting to `""`; the Python renderer's placeholder failure stays loud; the new build-blocking `check-prompt-mirror` gate asserts byte equality between the extracted Swift template and the seed, and its first run found a real one-byte drift (§9.2, §13 item 3) — a discriminating first result, not a pass-by-default. With no term, the clause is `""` and the composed prompts are byte-identical (pinned digest test, §12). Residual: R4 (the checker's emulation of Swift multiline-literal semantics) is checked by construction and fails loudly; acceptable.

### Surface 2 — Profile PII at rest (NFR-PI-001, FR-PI-003, FR-PI-015; name, term, DOB, GP, hospital, next of kin)

- **S — spoofing.** n/a: reads are the app's own code path, gated by device unlock and the app's key material; no identity claim exists at this boundary.
- **T — tampering.** A modified or spliced payload must not be half-honoured (no partial reads) or silently defaulted. Mitigations: the envelope binds its key (`{key, payload}`, key checked on read — verified); decode is whole-record, and a payload missing `name`/`addressAs` is unreadable, never defaulted; the exhaustive load-state mapping gives every probe/read/decode outcome a defined route; a corrupt payload is deleted best-effort once and cached; atomic temp-file + rename means a crash mid-write leaves the pre-existing record, and a failed write leaves both file and cache untouched (§5.1, §6, FR-PI-015). Grade: mitigated.
- **R — repudiation.** No attribution/audit of profile edits; no event on write failure (E3, user-visible only). Accepted by owner under OD-PI-5 with the project-wide biometric/PIN gate recorded as a follow-up (SD-6). Grade: accepted by owner.
- **I — information disclosure.** Zero plaintext copies: the encrypted-file channel with `.completeFileProtection` (verified in `EncryptedFileStorage.swift`), backup exclusion (verified), SHA-256 key naming, key material in the Keychain; DOB stored as year/month/day components and never spoken or composed; GP/hospital and next of kin have no prompt path at all. The only value-bearing artifact outside the store is the Piper synthesis temp WAV for the spoken ack, deleted after playback via `defer` (verified in `Speaker.swift`); no personalized audio is cached (ADR-06). Residual: the WAV's brief on-disk window is an evidence item for `security-test` (SD-5). Grade: mitigated with evidence owed.
- **D — denial of service.** A corrupt record must not loop (drop-retry) or stall startup. Mitigations: first load deletes best-effort once, then caches the outcome; no re-read loop (R7); the store's I/O is a single local read behind a lock; startup routing primes the cache with one synchronous read (§5.1, §9.4). Grade: mitigated.
- **E — elevation of privilege.** n/a: no privilege transition attaches to the store; the feature adds no auth gate and no new sensitive action (ADR-08).
- **Key management (asked).** No new key material of any kind: the store rides the same `MigratingEncryptedStorage` instance the coordinator hands every store; the placement policy keeps `user.profile` on the encrypted-file channel by default (`keychainResidentKeys` is a short explicit list — verified). Grade: fine.

### Surface 3 — Log surface (NFR-PI-002, FR-PI-015)

- **S — spoofing.** n/a (no identity claims on this surface).
- **T — tampering.** n/a.
- **R — repudiation.** Events carry outcome/error-code/duration only; no per-change attribution exists (folded into SD-6). Grade: accepted by owner.
- **I — information disclosure.** The leak channels are console writes, event metadata, and error bodies. Mitigations: the event catalogue is content-free (`outcome`, `error_code`, `duration_ms`, empty metadata; all three keys verified present in `LogSanitiser.allowedKeys`); `redactedKeys` gains `profile_name`, `address_as`, `date_of_birth`, `emergency_doctor`, `local_hospital`, and redaction runs before the allow-list filter — the fail-closed direction (verified in `LogSanitiser.sanitise`); `ProfileStoreError` carries no values; the ack events carry no content; guard rejection carries no metadata (§7.3, §7.4). The build-blocking gate `ios/tools/check-release-log-safety.py` gains the feature's roots; over those roots rule 3 fails any console write outside `#if DEBUG` (verified semantics) and rule 5 fails any event metadata key outside the shipped allow-list, which it reads from the source. Residual: the roots are the new files only; new code living in shared files (the wizard step views, coordinator additions) is not under rule 3/5, and rules 1–2 would not flag a profile-value console write there — SD-4, routed as an implementation action; the runtime choke point still contains the event channel. Grade: mitigated, coverage gap recorded.
- **D — denial of service.** Event emission is bounded: once per disk observation, never per cache hit, never in a loop (§5.1); guard events fire per read (per turn), not per retry. Grade: fine.
- **E — elevation of privilege.** n/a.

### Surface 4 — Egress (NFR-PI-003, FR-PI-009, FR-PI-008)

- **S — spoofing.** n/a; the term riding the cloud prompt is the intended disclosure under NFR-PI-003, not an impersonation.
- **T — tampering.** Could any other profile value reach a prompt or a payload? Mitigations (structural): the prompt read seam exposes exactly one string (`addressAsForPrompt`, plus the verbatim accessor the ack consumes — §5.3); the name is deliberately excluded from prompts (ADR-07); DOB/GP/hospital/next-of-kin/family/biometrics have no prompt or payload path (§9.4, ADR-11); exactly two `InterpreterContext(` construction sites exist (verified: 3601 and 1412) and both pass the same guarded accessor; zero new endpoints, request shapes, or clients (no client file is touched). Grade: mitigated; the snapshot API (`currentProfileSnapshot()`) is module-wide by nature, so confinement of the other fields is procedural plus review, which is the pre-existing pattern.
- **R — repudiation.** No new egress category, so no new consent or audit trail is owed; the existing engine-path instrumentation is unchanged. Grade: fine.
- **I — information disclosure.** The term enters the cloud prompt under the existing consent-gated flow (Open Decision 12, untouched); the disclosure obligation for the new fields is recorded as a release-checklist item (NFR-PI-011 #2, owner/compliance, 2026-10-13 window); the ack is local TTS and speaks only the template plus the term (§5.4, §9.4). Grade: mitigated; disclosure item carried for the owner.
- **D — denial of service.** n/a (egress volume is unchanged; the bounded term adds ≤ ~20 tokens).
- **E — elevation of privilege.** n/a.

### Surface 5 — Voice fingerprint enrollment data (NFR-PI-009, FR-PI-007)

- **S — spoofing (replay of enrollment audio).** The existing threat model applies unchanged; the mechanism, contracts, algorithm, and storage are untouched, and the step is a new call site (C12; verified call-site-only construction: the wizard hosts the existing session exactly as `VoiceSettingsView` does). Grade: accepted by reference (the existing voice-biometric threat model is the owner-accepted stance for this mechanism).
- **T — tampering.** Zero changes to the enrollment/verification code; no new input the wizard path adds beyond the existing session UI. Grade: fine.
- **R — repudiation.** n/a (existing flow).
- **I — information disclosure.** Biometric data stays exclusively in the Secure Enclave-backed store: zero biometric values in the new store, in logs, or in any outbound payload; no new permissions or purpose strings (`Info.plist` untouched — no modification in this worktree). Grade: fine.
- **D — denial of service.** Failure or skip advances the wizard; the session's existing phases render honest copy; no block. Grade: fine.
- **E — elevation of privilege.** n/a.
- **New-context check (verified).** Hosting the session before `coordinator.start()` is safe: `suspendForSampleCapture()` returns `true` when no live pipeline exists (verified at 10958), so the pre-start wizard context cannot wedge the suspension cycle. No new exposure was found in the wizard context.

### Surface 6 — Un-personalized fallback integrity and app-start routing (FR-PI-011, FR-PI-015, FR-PI-016, NFR-PI-010)

- **S — spoofing.** A forged "interview complete" status (tampering with the persisted step map) suppresses the route. Impact is low: the user is not sent to the interview; no privilege, no data exposure, and the feature simply stays un-personalized — the baseline the requirements mandate. Mitigation posture: the maps are app-container state behind device unlock; corrupt maps read as nothing recorded by the existing `status(of:)` rule. Grade: accepted (low).
- **T — tampering.** Corrupt or unknown step-map values must route, not trap. Mitigation: `coldStartInterviewRoute` reads via the existing persisted map and cached snapshot only; unknown values follow the existing ignore rule; `.unreadable` profile counts as mandatory missing and routes to About-you, which the ordinary Next-and-save path repairs; nil is a normal outcome (§5.8, C13 edge table). Grade: mitigated.
- **R — repudiation.** No new event for routing (E8) — the outcome is user-visible; no PII involved. Grade: fine.
- **I — information disclosure.** The routing decision stays on-device; no network, no logs, no new input (§9.4). Grade: fine.
- **D — denial of service (no crash, stall, loop, or trap).** Corrupt state at cold start routes from the first pending step; every step is skippable and the presentation is dismissible (OD-F3 / ADR-04 preserved); the decision is one synchronous evaluation, one-shot per process, no polling, no async, no timeout applies; the profile read is a single cached first read; a corrupt payload is deleted once, never retried (§5.8, §7.2 E8, §9.4). Grade: mitigated; the trap-freedom depends on the wizard's existing dismiss/skip affordances surviving the routed presentation — a verification item (SD-7).
- **E — elevation of privilege.** The route presents the wizard before `start()`; no auth flow is involved and no new privileged action exists. Grade: fine.
- **Fallback integrity (the surface's core).** Un-personalized means byte-identical prompts, the nil-seam wake path, no placeholder anywhere, and no partial application: the guard returns nil per read, the ack completes synchronously with no term, the store returns explicit `.absent` / `.unreadable`, and `addressAsClause(nil) == ""` is pinned by a digest test (§5.3, §5.4, §8, ADR-10). Grade: satisfied.

## Findings

| # | Finding | Security consequence | Severity | Route |
|---|---|---|---|---|
| SD-1 | Guard protection for instruction-shaped input is bounded by the shared marker table's English/transliterated list; the requirement's own example (`ignore your instructions …`) matches no entry and reaches the prompt as quoted data, as do all non-English shapes | The safe-outcome claim for out-of-table inputs rests on the quoted-slot framing and the absent capability; unspecified in the design and unproven until `security-test` exercises it | Moderate | design text (AM-1) + security-test |
| SD-2 | Quote-slot neutralisation covers ASCII `"` only; the Unicode quote family and backtick are not neutralised | A term can carry a stylistically closing quote inside the slot; no structural break is possible, and the 24-grapheme bound caps the payload — residual is semantic only | Low | implement (AM-2) |
| SD-3 | "Closes the wake gate synchronously at `begin`" does not match the shipped wiring: `noteSpeakingStarted` closes the gate inside `DispatchQueue.main.async`, so the begin-while-active state is reachable in a narrow window | The supersede path already handles that state (playback cancelled, speaking balanced, stale completion dropped, no event); worst case is a restarted greeting, not a corrupted capture or a security effect | Low (precision) | design text + seamless test (AM-3) |
| SD-4 | `FEATURE_ROOTS` gains the feature's new files, but new code in shared files (the wizard step views in `App/OnboardingWizardView.swift`, the coordinator additions) is outside the strict rules 3–6 | A Release console write carrying a profile value in those files would pass the gate; the runtime allow-list/redaction choke point still contains the event channel | Low–moderate | implement (AM-4) |
| SD-5 | The spoken-ack temp WAV holds the term in audio form in the sandbox temp directory until playback ends and the `defer` deletes it | Brief at-rest window for one value, inside the app sandbox, on an unlocked device; no persistent personalized audio by design (ADR-06) | Low (evidence) | security-test |
| SD-6 | No attribution or audit for profile edits; the Settings editor is plain (OD-PI-5) | A person with the unlocked device can read or change the term and the emergency fields; no record of who changed what | Low (accepted) | owner (already accepted) |
| SD-7 | Trap-freedom of the routed presentation and the low-impact status-tamper case (SD-6's surface-6 twin) are verification items, not design claims proven here | If the routed presentation lost its skip/dismiss affordances, a corrupt-state route could annoy; UI tests can pin it | Low (verification) | security-test / implement |

**SD-1 detail.** The guard pipeline is: quarantine (control-strip, whitespace collapse, marker removal, clamp 200) → strip-then-detect against the same single-sourced table → clamp 24 → quote neutralisation → nil on residual (§5.3, §9.3). Verified: the shared table is phrase-based and English/transliterated by deliberate design (its doc comment says Devanagari text must pass untouched, and the second copy of the table is prohibited project-wide). Verified: `ignore your instructions` — the example in NFR-PI-004's own acceptance scenario — is not matched by any listed entry, so the configured action (quarantine) does not fire for it; the term is composed into the clause as quoted data. The correct reading of the requirement is therefore that the *containment* for such inputs is the data-slot framing plus the structural absence of capability (no tool, no action, no write; routing and output validation unchanged), and that the *policy action* obligation applies to input that trips the table. Required: the design should say this explicitly (AM-1) and `security-test` must evidence both branches separately. Extending the shared marker family (`ignore … instructions` phrasing) is a project-level change to a single-sourced security artifact that would also alter the transcript path's behaviour — it is not a feature-local edit, and this review does not require it; it is recorded as an optional owner/architect decision.

**SD-2 detail.** The clause wraps the term in ASCII double quotes and neutralises only U+0022. Recommend extending the replacement to the quote family (U+2018/2019/201C/201D, backtick) or dropping those characters for prompt use; the stored and spoken term stays untouched (ADR-09 asymmetry). Low, but cheap.

**SD-4 detail.** The gate's rule 3 fails *any* console write outside `#if DEBUG` in a feature root, and rule 5 fails unlisted metadata keys — both verified in the judging engine. The design routes the new step views and the coordinator additions through paths the strict rules do not scan. Recommendation: land the new step views in a dedicated file (for example `App/ProfileInterviewSteps.swift`) that can be added to `FEATURE_ROOTS`, or add a targeted symbol-scoped rule; keep the designed roots as they stand. Either is an implementation task; the runtime fail-closed choke point means no open leak channel is implied.

## Evidence obligations for `security-test`

1. In-table marker term → quarantine fires, the turn runs un-personalized, the composed prompt is byte-identical to the no-term baseline, the event carries no metadata.
2. Out-of-table payloads — the requirement's example (`ignore your instructions …`) and a Nepali instruction-shaped term — with an A/B assertion that routing for a fixed utterance is unchanged, no action triggers, and no profile write is reachable through prompt output (SD-1).
3. Quote-family break attempts (U+0022 handled; U+201D / backtick recorded) and grapheme-boundary truncation (Latin plus Devanagari conjuncts) against the 24-grapheme bound and the pinned budget (SD-2, §9.1).
4. A personalized Release-build session with console, log files, and telemetry inspected: zero occurrences of any profile value; the extended log-safety gate exits 0 (SD-4, NFR-PI-002).
5. Container inspection: no plaintext profile value anywhere (store, temp files, debug artifacts); the ack WAV is gone after playback; keystore access is required to read the payload (SD-5, NFR-PI-001).
6. Corrupt-payload run: deleted once, never partially applied, no loop, startup unaffected (FR-PI-015).
7. Offline full journey (interview, wizard close, wake ack, on-device replies, Settings edit): zero network requests attributable to the feature (NFR-PI-003).
8. Ack failure injection: unresolved template, timeout, cancel — silent start, completion exactly once outside `cancel()`, speaking bookkeeping balanced (NFR-PI-008, §7.1).
9. Cold-start routing: corrupt step map and unreadable profile → no crash, stall, loop, or trap; the presentation's skip/dismiss affordances are present (SD-7, FR-PI-016).
10. Voice fingerprint: diff-level evidence of mechanism/storage/permission non-change; no biometric value in the new store, logs, or payloads (NFR-PI-009).

## Limitations

- The budget, seed-byte, and digest figures are relied on from `review-l2`'s independent reproduction rather than re-measured here; this review verified the security mechanisms and their code anchors.
- The live device behaviours this report treats as evidence obligations (WAV deletion, offline journey, Release log inspection, device-persistence of the encrypted store) cannot be proven by reading code; they are routed to `security-test` by design.
- Model-side compliance with quoted-slot content is not a property any design can guarantee; the assessment bounds the *consequence* (no capability, no action, no write) rather than the *lure* (SD-1).

## Decision

decision: SECURITY-GO

**Rationale.** All six mandated surfaces plus the FR-PI-016 routing amendment have a designed mitigation for every STRIDE threat identified; the strongest mitigations are structural (whole-record decode, one-string prompt seam, fail-closed redaction, absent capability) rather than procedural. No finding blocks implementation: SD-1 is a containment-statement and evidence-design obligation whose safe outcome is already the design's architecture; SD-2/AM-2 and SD-3/AM-3 are cheap precisions; SD-4/AM-4 is a tooling-coverage improvement behind a working runtime choke point; SD-5 and SD-7 are evidence/verification items; SD-6 is an owner-accepted residual already on record. The amendments are routed non-blockingly so `plan-tasks` can fold them into the implementation slices (the seed/template/mirror-gate unit and the store-first ordering stay as designed). The feature proceeds under the workflow exit condition `review.decision == "SECURITY-GO"`.
