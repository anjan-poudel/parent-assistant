## Category verdicts

### Category 1 - Prompt injection via address-as/name into shared templates - PASS
The only profile string that can reach a prompt is the address-as term, and it passes one read-seam guard in a fixed order: quarantine through the shared input sanitiser (control strip, whitespace collapse, marker removal), strip-then-detect against the single-sourced marker table, a Character-bound clamp to 24 graphemes, then quote-family and backtick neutralisation to a plain apostrophe, with nil on any residual. A term that trips the shared table is dropped for the turn and the assistant runs un-personalized; the quarantine event carries outcome only. Out-of-table instruction shapes, including non-English text the English/transliterated table cannot know, are contained as data rather than detected: the value can only appear inside the fixed quoted slot of the clause, the clamp bounds its size, and the guard holds no reference to routing, reply-style rules, authentication, safety behavior, or the store. The A/B test drives the real router through the personalization seam with an English out-of-table payload and a Devanagari payload: routing unchanged, spoken reply equal to the no-term run, no save or compose or rephrase or contact-search action, prompt differs only by the clause (the out-of-table A/B test). The in-table case pins the no-term digest baseline (the in-table digest-baseline test). Quote neutralisation and the grapheme clamp are unit-tested; the worst-case composition stays inside the pinned ceiling (2,586 of 3,000). The clause appears exactly once at its exact anchor in each of the three builders, and the seed-mirror gate proves the training seed equals the Swift builder byte-for-byte (2717 bytes, 4 placeholders). The user's name never enters a prompt. The recorded term reaches the wake acknowledgment verbatim (the accepted ADR-09 asymmetry) while prompts receive the neutralised prompt-side copy only. Unchanged by rework pass 1.

### Category 2 - PII at rest (store + WAV window) - PASS (static half; device half declared not-run)
The profile record is written through the encrypted file storage decorator: atomic write with complete file protection on every write, the file name is the SHA-256 hex of the store key, and the file is marked excluded from back-up. The envelope is decoded whole; an authentication or decode failure surfaces as unreadable, never as plaintext. The store maps the disk observation exhaustively: an unknowable probe reports a read failure and deletes nothing (the store may hold a good record); a present-but-corrupt payload reports decode failure, is deleted best-effort exactly once, and only a successful delete caches the absent verdict, while a failed delete caches unreadable so no per-read delete loop can form. Saves are main-queue-only by precondition, with file I/O behind the lock, and the cache swaps only on success. Every store and personalization event is content-free: outcome plus a fixed error code, empty metadata. Temporary WAVs from the acknowledgment speaker are removed in a defer on every exit of that path. The enrollment template lives in a Keychain-backed store, not in the file store. Device-level inspection of the on-disk window (obligation 5) is declared not-run; the static controls listed in this section are what this environment can attest. Unchanged by rework pass 1.

### Category 3 - Log surface - PASS

The observability event carries outcome, error code, duration and an empty metadata map only; every profile emit site passes fixed codes and no text. The release gate was re-run by this review on the post-rework tree: exit 0, 24 fixtures over 12 rules, every rule load-bearing, and FEATURE_ROOTS covers all nine feature files including the wizard steps file (AM-4). No print and no raw error description appears in any feature file, including the reworked step and the new kin-designation tests.

### Category 5 - Voice fingerprint data untouched - PASS
The worktree delta contains no change to the biometric mechanism: the speaker-biometric service, the enrollment recorder, and the app's Info.plist are not in the modified set (re-confirmed on the post-rework tree). The wizard step constructs its enrollment session exactly as the Settings screen does, same embedder selection, same Keychain-backed store, same coordinator-owned recorder and pipeline suspender, so the wizard and Settings enroll into the same template store. Rework pass 1 closed the one lifecycle gap this category carried: the step now has the Settings screen's mid-recording teardown (onDisappear awaits the session's stopRecording), so leaving the step by any route while recording stops the capture and releases the pipeline suspension instead of leaving the pipeline suspended or the mic tap installed. stopRecording is a no-op unless a sample is being recorded, and on the recording path it is also the normal resume route; it carries no logging, no egress and no permission need, and the scoped UI walk exercised the handler on the live path. No biometric value appears in the profile payload, in events, or in logs. This discharges the diff-level non-change obligation (10), now including the teardown.

### Category 6 - Un-personalized fallback + FR-PI-016 routing - PASS
Routing is a pure static rule on onboarding state (first pending step, mandatory fields recorded) with 12 executed tests covering fresh start, resume, complete, soft-skip, mandatory gates, never-past-about-you, corrupt and wrong-typed field maps, unreadable record, and trim parity. The cold-start shell is one-shot (a single check with an XCTest-configuration boot guard) and captures the wizard start; a corrupt or unreadable store routes to the right step without a crash, stall, or trap; the simulator covers this (obligation 9). When the store is unreadable or the term is withheld, the personalization seam yields no term and the prompt falls back to the pinned no-term digest baseline: the assistant runs un-personalized. Acknowledgment failure injection (obligation 8): a template that cannot produce a spoken phrase emits `wake_ack_failed` / `template_missing` and completes synchronously; the hold timeout cancels playback and settles `hold_exceeded`; cancel and supersede settle with no event; every path funnels through one settle that balances the speaking bookend exactly once, and per-ack epochs make stale tails inert. The acknowledgment class re-ran 10 of 10 green in isolation after two wall-clock flakes under CPU churn; the flakes are attributed to CPU contention, not to the state machine (sources unchanged, the 188/188 run green). Rework pass 1 additions checked: the enrollment teardown in Category 5 also releases the pipeline suspension on every mid-recording exit (the wake path's latch cannot stay held past the step), and the one-tap kin designation was extracted as a pure plan function (the tapped contact flagged, each currently flagged contact cleared with its stored values carried verbatim, untouched unflagged contacts not planned), executed by the contacts step through the existing contact-update seam with one write per planned entry and no other write; it adds no logging and no egress, and its four tests pin the plan.

### Category 7 - Secrets in output files / error leakage - PASS
A pattern sweep of the feature and new test files for credential shapes (provider key prefixes, authorization-header values, PEM markers) returns nothing; fixtures are synthetic, including the new kin-designation tests (single-letter names, a placeholder phone number, reserved example.com addresses for the field-preservation case), with no real contact data. Error surfaces are fixed codes and localization keys: no raw error description and no print in any feature file, store failures reduce to a single write-failed case, and the personalization, store, and acknowledgment events carry no free text. The seed and prompt artifacts passed the implement-notes pre-scan (secrets, injection, contract) as recorded, and both static gates re-run here also pass on the post-rework tree.
