### T-017 — `SceneTextSanitiser`

Pure, total, no I/O and no clock. `sanitiseForEgress(_:maxLength:)` returns one of three verdicts:

- `.sendable(text)` — ordinary text passes through unchanged;
- `.truncated(text)` — over-long text, cut with `String.prefix(_:)` (grapheme clusters, so a
  Devanagari conjunct cannot be split), **still sent**;
- `.quarantined(reason)` — a residual marker after stripping, or nothing usable left; **carries no
  text at all**, so there is nothing to send and nothing to speak.

The order is strip → detect → decide, exactly as the design fixes it: the stripping half is
`InputSanitiser.sanitise(raw, level: .quarantine)`, and the quarantine authority is the shipped
detect-only seam `InputSanitiser.containsInjectionMarker` applied to the **stripped** text. A
residual (a removal reconstituting an earlier shape) is the quarantine trigger. Inverting the order
would both quarantine strings the shared sanitiser already made safe and let a reconstituted shape
through.

`bound(_:maxStrings:maxCharacters:)` splits an over-large set into sequential batches, order
preserving, never dropping a string; `sanitiseBatch` + `record(_:on:)` report a quarantine as a
**count and nothing else** (`text_quarantined`).

### T-018 — `GeminiClient.translateStrings`

A new method on the **existing** `send(_:)` chokepoint — same auth header, same timeout, same cost
governor, same provider-block handling. The request is built as:

```swift
GeminiRequest(contents: [.init(parts: [.text(prompt)])],
              generationConfig: .init(responseMimeType: "application/json"),
              tools: nil)
```

One text part, `tools` explicitly nil (so no search grounding and no capability the model could
invoke), and **no parameter on the signature** through which an image, media, inline-data or tool
part could be attached — there is no overload that adds one either. Scene strings never enter the
instruction region: they travel as a JSON array of `{ id, text, sourceLanguage? }` appended after it,
so a string written as a directive is a value in a structured document, and JSON quoting keeps
newlines/brackets/quotes from changing the request's structure or its id set (AM-10).

The consent proof is a required parameter of type `LiveTranslateConsentGate.Grant`, whose initialiser
is `fileprivate` to the gate — the only producer is `authorize()`. A proof whose `disclosureVersion`
does not match the copy in force fails closed **before anything is built**.

The response is validated against exactly the requested ids: unrequested ids are discarded and
counted, non-string values are rejected, empty values are rejected, and a value longer than
`translationMaxLengthRatio * sourceLength + translationMaxLengthAllowance` is rejected as unusable.
A body that is not a JSON object is a typed, content-free defect (row 17); no partial translation is
produced from it.

### T-019 — `CloudTranslationTier` (actor)

One cycle runs in the design's fixed order: need (dictionary/cache) → sanitise and quarantine →
consent → budget → claim → one batched request per batch → validated decode → store → release. The
retry policy lives here, not at a call site. Every claimed key is registered with the gate before any
`await` and released in a `defer`; the indicator's show/hide bracket is the shipped
`CloudActivityIndicatorModel.withRequestInFlight`.

Consent is re-read **immediately before every attempt**, minting a fresh per-attempt proof (AM-1); a
withdrawal between attempts ends the cycle before a request is built, and a cancellation-shaped
failure is terminal and never retried — the reason reported is then the freshest gate read, so a
withdrawal is named as the consent failure it is rather than as a transport fault.

A key already claimed in flight is not re-requested: the second cycle awaits the owner's task and
adopts the same terminal outcome for its own region (AM-8 / CL-1). The cost latch is the feature's
only added state; the day's counting stays in the shipped governor at the transport boundary.

## 4. Decisions made during implementation

1. **Strip-then-detect is preserved and pinned.** The residual fixtures are asserted to actually
   produce a residual (`InputSanitiser.sanitise` still matches afterwards) so the test fails if the
   order is ever inverted rather than silently passing.
2. **`.quarantined` carries no text**, so "never sent, never spoken" is a property of the type
   rather than a rule a caller must remember; the overlay still shows the elder's own text, read from
   the region it already owns.
3. **A `Grant` is per attempt, not per cycle.** The tier calls `gate.authorize()` again immediately
   before every attempt (AM-1) instead of carrying the first proof forward; a proof that does not
   match the disclosure copy in force fails closed before anything is built.
4. **One call site, enforced by scan.** `testAM9TheSignatureHasNoMediaToolOrAttachmentParameterAndExactlyOneCallSite`
   counts `translateStrings(` call sites across the app sources and fails if the set is not exactly
   `{GeminiClient+Translate.swift: 1 (the declaration), CloudTranslationTier.swift: 1 (the caller)}`.
5. **Deadline seam in `Duration`, not nanoseconds.** The injected sleep seam takes a `Duration` (iOS
   16 supports `Task.sleep(for:)`), which removed a unit conversion and a `UInt64` literal that the
   shipped banned-literal scan flags. The deadline itself is `cloudDeadlineSeconds`, which is derived
   from the shipped `GeminiClient.Config.default.timeoutSeconds` plus `cloudDeadlineGraceSeconds`
   (CL-8) — the client timeout is not re-stored anywhere in the feature.
6. **The deadline race distinguishes "elapsed" from "sleep cancelled".** A withdrawal cancels the
   in-flight task (and with it the deadline tick); reporting that as `cloudDeadlineExceeded` would
   have been a false cause, so the tick returns a third state and the work child's terminal outcome
   is awaited instead.
7. **In-flight claims are registered before any `await`.** The claim (`inFlight[key] = task`) and the
   gate registration happen synchronously in `runClaimedBatch`, so a second cycle can never
   interleave between the check and the request. Bridge tests make this deterministic with an actor
   latch/arrival pair rather than timing.
8. **Per-request short indices as item ids** (`"0"`, `"1"`, …) — duplicate source strings stay
   unambiguous, and a forged id cannot collide with a region id because region ids are adopted from
   the request, never from the response.
9. **Deviation, test-only evidence accessors.** `CloudTranslationTier.isCostLatched`,
   `inFlightKeyCount` and `deadlineSeconds` are read-only members added so the latch, the release
   invariant and the deadline derivation are assertable rather than implied. They have no setters and
   are not on any production call path.
10. **Deviation, injected sleep seam.** `CloudTranslationTier.init` takes a
    `@Sendable (Duration) async throws -> Void` defaulting to `Task.sleep(for:)`. Production wiring is
    unchanged; tests use it to decide the deadline race without a wall-clock wait.
11. **Bounding lives in the sanitiser, batching in the tier.** `SceneTextSanitiser.bound` is pure and
    reusable; the tier calls it with the config's two batch bounds and emits
    `translation_batch_requested` per batch with `stringCount`/`batchIndex`/`batchCount` only.
12. **The cost latch is the only added state.** `allowsCall()`/`recordCall()` remain the governor's,
    counted at the transport boundary; the tier's `cost_exhausted_latched` is additional to (not a
    replacement for) the governor's own events.

## 7. Open items

1. **T-019's task file contradicts binding CL-3 on cache attribution.** The task file's CL-3 note says
   "a cache-written cloud translation served later attributes dictionary, because it did not
   translate this time". The binding amendment CL-3 (and FR-LCT-015 condition 1, and
   `specs/review-l2.md` line 210) require the opposite: a cached cloud string must report `.cloud`, so
   the overlay's in-place rule (tier 0 only) can never draw it in place. The implementation follows
   the amendment — a single `ResolutionOrigin.tier` mapper where a cache entry is attributed to the
   layer that produced it. The task file was left unedited (outside this group's files; the brief
   forbids editing `specs/design-component.md` and this is the same class of wording defect).
2. **Provider-reason residual (SD-6 / SR-1), recorded rather than papered over.** A provider-side
   refusal is reported by the shipped client's own `gemini_blocked` event carrying the provider's
   block reason on component `gemini_client`. That emission is pre-existing and is not duplicated by
   the feature; the feature maps the refusal to a constant token and copies no upstream-derived value
   into its own events (asserted). The prompt boundary cannot make the provider's own classification
   of a request disappear.
3. **`TranslationError.responseUnusable(.empty)` is unreachable through the client**, because
   `GeminiClient.send` guards an empty candidate text first and surfaces `GeminiClientError
   .emptyResponse`. Both paths are covered (parser level and client level); the duplicate branch is
   stated in the source rather than silently dropped.
4. **`SceneTextSanitiser.bound`'s oversized-single-string branch is unreachable through the live
   path** because per-string truncation runs first. It is kept (and tested) so the function stays
   total and never silently drops a recognized string.
5. **Simulator contention is a live risk for every other group's gate** (finding 2). It cleared here,
   but a gate run that reports `Early unexpected exit … never finished bootstrapping` should be read
   as contention first, not as a code defect — and re-run before it costs anyone an hour.
6. **The private simulator used during the contention window has been deleted**
   (`xcrun simctl delete TG06-iPhone17`), so no stray device is left on the machine. Its run is still
   cited above as corroborating evidence; both reported results come from the same command.
7. **`./build.sh test:impact` fails in this worktree, on 21 tests outside this group** (see §5). Those
   are pre-existing/in-flight failures in the intent-engine and voice areas and are not caused by,
   nor fixable from, TG-06's files.
