## Decisions made during implementation

- **Task IDs are T-070–T-079, not T-062 onward — and the group is ten tasks, not eleven.** The brief assumed T-062 was free; it was not. `T-061`–`T-069` are TG-11's (drafted in parallel in `.claude/worktrees/tg11-robustness/`, unmerged), and `T-080`–`T-089` are TG-13's (`.claude/worktrees/tg13-benchmark/`, also unmerged — and TG-13's index already links into this group). That leaves exactly ten contiguous IDs. The brief's eleven tasks therefore became ten: latency-budget verification and default-flip end-to-end verification are now **one** task (T-078) with two labelled parts. This is recorded as a real loss, not a tidy-up — the group now has two verifications rather than three, so T-077 (the safety gate) must not be folded further.
- **The ID collision was caught late and would have been silent.** The first draft allocated T-069–T-079 against the main checkout's task tree, which at that moment showed TG-11 ending at T-068. While this design was being written, TG-11 added a ninth task (`T-069-evidence-pack-gap-register.md`, its closing evidence pack), taking the ID. The lesson is recorded in design §3: **task IDs are allocated against every worktree on disk, not only the main checkout, and the check must be re-run immediately before allocation** because a parallel group can grow mid-draft. TG-11's files live only in its own worktree, so a check that reads the main checkout alone cannot see them.
- **Task IDs shift rather than collide, following the TG-10 precedent.** When T-051 was taken, TG-10 recorded *"the whole group shifted by one, keeping the brief's phase order and titles exactly."* The same rule is applied here, extended to a group that grew rather than merely shifted.
- **A safety-first reading of the brief, made structural.** The brief required that "emergency/med-ack/keyword paths bypass canonicalization". The design does not leave that as prose: D-1 states it, §4.7 gives a frozen set and a two-clause equality invariant, the table validator refuses any entry touching a negation marker (refusing the **whole table**, not the entry), and T-077 must demonstrate the gate **failing** on a deliberately unsafe rule before its passing result is trusted. That negative arm is a Definition-of-done item, not a suggestion — a gate never observed failing is not known to be a gate.
- **The highest-severity finding is a latency bound, not an accuracy one.** The encoder times out at 2.0 s with zero retries, the picker brain at 10 s with one retry, and `LocalBrainChain` passes no remaining-time budget to its stand-in — so a worst-case escalated turn is **12 s** against NFR-002's 4 s, in the mode where the user has already waited for one model to fail. The cascade ships `cascade: nil` (default OFF), which is the only reason this has never been observed. The design makes a turn-level deadline a **precondition** of the flip (Stage 1 condition 1.9) rather than a follow-up, and specifies the fix in the chain rather than by lowering the picker's 10 s timeout — that timeout serves the single-brain default too, where a slow answer beats no answer.
- **The flip is two changes, and the design says so.** `#if INTENT_ENCODER` compiles the encoder path out of a release build deliberately (*"impossible for the encoder to become the local brain in a release build by accident"*), so "encoder-first is the default" requires both the compile-time condition changing and `isCascadeEnabled` defaulting true. A reader could otherwise believe the flip is a UserDefaults default. **Stage 0 is currently RED** — the shipped artifact fails `emergency_recall` (~0.9375 against a 1.00 hard gate) and `closed_intent_accuracy` (~0.53 against 0.95) — so the honest current state of the group is "the flip is designed, gated, and not reachable yet".
- **Evidence discipline was made mechanical, not aspirational.** Per the mid-task directive: every variant-table entry is sourced either from corpus frequency evidence (`occurrences ≥ 1`, with row ids, on the pinned revision) or from a cited authored example set (`≥ 2` examples), and the validator refuses the file otherwise — so an unsourced rule **cannot be written** rather than being caught in review. Every losslessness claim carries an explicit gate. Every cascade flip condition is a numeric comparator on a named revision. §14 is the ledger (`claim → measurement → threshold → fixture id → corpus evidence`) with nine gaps (G-1…G-9) each naming what would close it, and R-5 plus open question 1 state plainly that the expected effect size is **unmeasured** and may be zero, with the orthographic half being the likelier source of value.
- **The plan.md counts were recounted from disk, not propagated.** This tree holds TG-01–TG-10 plus TG-12 (11 groups); the verified totals are **59 parent tasks across T-001–T-079**, with T-061–T-069 (TG-11) and T-080–T-089 (TG-13) reserved and excluded from the total, since those groups are not in this tree. The Task Group Summary total was corrected to match, and a note records how to reconcile when the parallel groups land. No task ID was renamed or reused.
- **Risk numbering continues the existing list.** `plan.md` gains items **32–35** (the 12 s cascade bound; the negation-collapse safety hazard; the possibility that canonicalization buys nothing; the inert dialect axis). The TG-12 paragraph in "Security blockers" follows the existing "No new security BLOCKERs are introduced by X" pattern and was placed with the other group paragraphs rather than inserted mid-list.
- **The TG-10 tension is honoured, not worked around.** TG-10's invariant 3 says *"No new threshold. The band policy … is not modified by the loop."* The design restates it as D-7: the cascade's threshold **is** `IntentRouter.Config.default.acceptThreshold`, so there is nothing separate to tune, and the loop may re-fit `calibration_temperature` (which moves *confidence*, and therefore which band an output falls into) but may never move the band itself. The one genuinely new privacy question — whether a variant pair mined from a user's correction is content under TG-10's hashed-egress contract — is recorded as gap G-3 and **referred to TG-10's T-053/T-059 rather than answered**, and T-079's Definition of done forbids settling it by implementing an egress path.

## Corrections and findings recorded in the design

- **A stale citation, corrected.** The encoder design cites the emergency phrase list at `CommandRouter.swift:1403-1408`. Read against the file, the list is at **`:1468-1473`** (17 phrases: 7 English + 10 Nepali); `containsPhrase` is at `:1439`, `containsToken` at `:1448`, `routeSafetyNet` at `:1494`, the denial guard at `:1508-1517`, the med-ack lists at `:1519-1534`. The encoder spec's *substantive* claim is correct. All citations in this group's artifacts use the verified numbers.
- **A brief assumption, corrected.** The brief places TG-11's docs under `tools/train-intent/`. They are not there — that path holds only T-033-era material. TG-11's task documents live in the **TG-11 worktree** and are unmerged, so every link this group makes into them resolves only once TG-11 lands. TG-11 does *touch* `tools/train-intent/` (it amends `annotation_rules.yaml` and adds `eval/order_permutation.jsonl`, `eval/dialect_holdout.jsonl`).
- **A vocabulary mismatch, recorded rather than assumed away.** The brief named Eastern/Central/Western/Terai. The **shipped** vocabulary is `eastern | doteli | default`; TG-11's five-value hypothesis (`standard, eastern, central, western, terai`) is an unreviewed working hypothesis in its own worktree, not shipped nomenclature. The design consumes TG-11's `T-062` resolution rather than assuming one (D-9), and defines selection so that a wrong label can only **fail to fire** a rule — never fire another region's.
- **A limiting finding.** The dialect label is read from `DialectPreference`, whose only writer (`WhisperKitSpeechRecognizer.applyDialectLabel(_:)`) has **no production callers** — the embedding/classification bridge beside it is documented as *"the future enrolment flow"* — so the persisted label is `.default` in the field, and the shipped `SEED-CENTROIDS` table could not clear its own 0.6 gate anyway (a test asserts *"A seed table must never classify anything"*). Consequence: the per-dialect tables are **inert until an enrolment flow and a calibrated centroid table land**, and the orthographic/pan-regional half is the half that can act now. Recorded in design §3 and as `plan.md` risk 35. The group neither builds an enrolment flow nor populates the centroid table (both out of scope).
- **A band-integrity observation.** The accept band exists as **three independent 0.7s**, one of them a hard-coded literal not derived from the constant (`CommandRouter.swift:1139-1155`). The flip does not touch the band, so this is not a flip blocker — but "the encoder serves at exactly what the router bands at" is a claim the design leans on, and a future band change would need all three sites. Recorded as risk R-11 with the repair explicitly out of the group's scope (a `CommandRouter` edit).
- **A `CommandRouter` whitespace hazard, generalised.** The net already whitespace-canonicalises its own copy of the transcript (`:607-620`, WhisperKit join behaviour, pinned rev `ea872ffd`). O-6 (mis-segmentation repair) is that behaviour generalised, and it is the highest-risk rule in the set: a table that "repairs" `ना खाए` into `नखाए` changes a two-token refusal into one token. It may not produce or consume a token intersecting the safety set, and any such candidate repair is a structural error.
- **A span-mapping consequence the canonicalizer creates.** The encoder's F-4 requires `transcript[start:end] == spanText`. Canonicalized input forces an offset map back to the original, and a **widened** span is safe for a substring match and unsafe for a resolution — so a required span (`contact` for `call`/`send_message`, `time` for `set_reminder`) that maps with widening causes the interpreter to **abstain** rather than resolve. Authoring therefore prefers length-preserving substitutions, and length-changing entries must record how often they fire on `contact`/`time`-bearing rows so the abstain cost is visible before authoring rather than after.

## Open questions (carried into the task files, not silently resolved)

- **OQ-1** — does canonicalization pay for itself on this encoder? E-6 is unmeasurable until a canonicalized corpus exists (after T-075/T-078), and the honest prior is that the 117M-parameter student may generalise to some attested variants unaided. The design is built so that "+0" is printable.
- **OQ-2** — is `escalation_rate ≤ 0.35` the right bound? It is a **chosen** number, and T-071's first run should be treated as evidence about the threshold, not only about the artifact.
- **OQ-3** — does the sub-band belong in the confirmation flow rather than the cascade? `bandChecked` already routes tier-`.confirm` sub-band actions into confirmation; doing the same for tier-`.free` would avoid the double-brain cost at the price of a spoken confirmation. T-071's agreement rate decides it.
- **OQ-4** — what happens when the enrolment dialect label is wrong? A wrong label can only fail to fire a rule, never fire another region's; whether the failure is silent or surfaced is T-072's UX decision.
- **OQ-5** — does the picker rung eventually want canonical input? §4.6 says no today, on measurement grounds; if dialect-corrupted utterances are disproportionately the long tail, the argument inverts, and T-071's reason breakdown is what would reveal it.
- **Unresolved by design** — gap G-3 (whether a variant pair derived on-device is content under TG-10's hashed-egress contract) is referred to TG-10's T-053/T-059. T-079 may not settle it by implementing an egress path.
