## Description
Create the slot-clock component: the `MedicationSlot` enum (morning / afternoon / evening), the `MealRelation` enum (before meal / after meal), the structured quantity types (`MedicationQuantity`, dose unit) used by FR-MSR-001, and `MedicationSlotClock` itself — the total, deterministic, fail-closed mapping from a slot to exact hour/minute `DateComponents`, with household defaults morning 08:00, afternoon 13:00, evening 19:00. Ship the thin store (IF-3/IF-4) over the encrypted local storage key `medication.slot_clock`, one writer, validation before persist. A mapping that cannot yield a determinate hour/minute resolves to a typed failure — never a coerced or guessed time. Custom decode merges per-slot defaults so a partial payload still yields a total mapping (NFR-MSR-006).

## Acceptance criteria

```gherkin
Feature: Deterministic slot-to-clock mapping with family defaults

  Scenario: Default mapping arms the reminder at the mapped clock time
    Given a household with the default mapping (morning 08:00, afternoon 13:00, evening 19:00)
    And an entry with the morning slot, before meal
    When the day's reminders are created for that entry
    Then the reminder is armed for 08:00
    And the acknowledgement window, re-fire schedule and escalation deadline derive from that same 08:00 scheduled time

  Scenario: The family changes the household mapping
    Given the family sets the morning slot to 07:30 in the medication settings
    When the schedule is re-armed
    Then the morning entry's reminders resolve to 07:30
    And resolving the same entry and mapping again yields the same 07:30 result (deterministic)

  Scenario: No determinate time means no armed reminder (failure)
    Given an entry whose slot cannot be resolved to a determinate hour/minute under the household mapping
    When the schedule is armed
    Then no reminder is armed for that entry
    And the condition surfaces as an error
    And no implicit or guessed clock time is used
```

Concrete checks: `resolve` never produces a second/fractional component; identical inputs always produce an identical result across repeated calls; an invalid stored mapping (missing hour or minute, out-of-range values) decodes as-is and fails resolution with a typed error instead of being repaired.

## Implementation notes
- Fail-closed resolves the FR-MSR-002 scenario "no determinate time means no armed reminder"; the arming consumer (T-008) surfaces the error as the PII-free `medication_slot_unresolved` event with the slot only.
- Constants: the three default times are named constants in this file; the exact-time arming shape of the shipped scheduler is preserved (hour + minute only).
- Store: `EncryptedLocalStorage` write/read; the save path runs `validate` first; no other writer exists in the feature.
- No new egress, no LLM symbols, no PII in any error text.
