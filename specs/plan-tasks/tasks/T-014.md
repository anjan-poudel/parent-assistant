## Description
Let a free-form event's side-index carry zero or one instruction without losing the photo, add a strict snapshot for the orphan sweep, and repair the `setPhotoFilename` mutation so it no longer wipes the instruction field. The store keeps its shipping `Bool` write convention; the service seam translates that to the typed write error in T-015.

## Implementation notes
- Follow design §2.13 (C12), §3.6 (IF-26/IF-27), §4.5 (EventExtras delta and the `setPhotoFilename` fix pair), §5.9 (read failure modes), §11.3 F (preservation).
- **OI-1 exception:** `EventExtrasStore.setInstruction(_:forEventId:) -> Bool` stays a deliberate, recorded exception to the typed-error rule. The service translates `false` to `InstructionWriteError.persistenceFailed`. Do not change this store to a `Result`.
- The mutation bug is real: the current `setPhotoFilename` writes a fresh `EventExtras(photoFilename:)`, which would erase an instruction. Repair both setters so each preserves the other field.
- Tolerant decode: `instruction = try? container.decodeIfPresent(Instruction.self, forKey: .instruction)`. A malformed nested instruction reads as nil rather than losing the row.
- `snapshot() -> [String: EventExtras]?` returns nil on any read failure. The legacy `all` property keeps its empty-on-failure convenience for existing callers; the sweep uses only the strict snapshot.
- The extras payload still lives under one encrypted key. Do not add per-event keys or a new store.
- The store does not delete media. Media deletion belongs to the event service transaction (T-015) and the sweep (T-025).
