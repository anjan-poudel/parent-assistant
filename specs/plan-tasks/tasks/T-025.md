## Description
Complete the composition root: build the fired-screen value from the notification context, route a routine tap through the three explicit cases, dismiss the screen, and run one orphan sweep at launch using strict reads. The sweep must treat nil as unknown, never as empty, or a transient read failure would delete a family's instruction videos.

## Acceptance criteria

```gherkin
Feature: Coordinator presentation and orphan sweep

  Scenario: A foreground firing composes the typed content
    Given a fired entry, a fire context with hadInstruction true and a delivery date
    When presentRoutineVisualAids runs
    Then FiredRoutineVisualAids.Content.reminder carries the title, aids, instruction, expectsInstruction and firedAt
    And expectsInstruction equals the context's hadInstruction
    And the published value drives ContentView's overlay

  Scenario: A tap with a live owner opens the instruction screen
    Given a tap sink call with an entry whose instruction is present
    When presentRoutineInstructionTap runs
    Then the published content is reminder with that instruction
    And no notice is shown

  Scenario: A tap with a deleted owner shows the notice
    Given a tap sink call with a nil entry
    When presentRoutineInstructionTap runs
    Then the published content is unavailable
    And no title or time is claimed
    And dismiss clears it

  Scenario: Dismiss clears the fired state once
    Given a published fired value
    When dismissFiredRoutineVisualAids runs
    Then the published value is nil
    And a second dismiss is a no-op

  Scenario: The launch sweep keeps bytes when a source is unreadable
    Given the routine strict read returns nil and the event snapshot returns readable rows
    When the sweep runs at launch
    Then routine files are kept
    And event files follow the live rules
    And the sweep reports a partial count rather than a total
    And no file is deleted inside the 60 second grace

  Scenario: The live set is built from instructions, never from filenames only
    Given an owner whose instruction kind is video and whose file is missing
    When compose runs
    Then the owner is treated as live
    And no IO occurs during compose

  Scenario: The sweep is not part of initialization
    Given the coordinator is created
    When init returns
    Then no sweep has run and no file IO has occurred
    And the launch path starts the sweep once
```

## Implementation notes
- Follow design §2.15.3–§2.15.5 (composition, tap routing, sweep), §3.6 (IF-32), §4.9 (`LiveInstructionOwners`), §5.9 (orphan safety), §7.4 (single launch sweep), §11.3 K (orphan safety).
- **M-4 downstream:** the sweep reads `routineScheduler.entriesIfReadable()` and `eventExtras.snapshot()`. `nil` means unknown and keeps all bytes for that source. Never substitute `loadEntries()` or `all`.
- The live set contains every owner whose current instruction kind is video, even when the file is missing. `compose` performs no IO; the coordinator supplies the two reads.
- `presentRoutineVisualAids(for:context:)` builds `.reminder(title:aids:instruction:expectsInstruction:firedAt:)`. `presentRoutineInstructionTap(entryId:entry:firedAt:)` builds `.reminder` when the entry exists and `.unavailable` when it is nil. `dismissFiredRoutineVisualAids()` clears the value.
- Register `RoutineVisualAidFireHandler` with both sinks and `FreeFormEventFireHandler` with its existing sink. Do not change `NotificationFacade` or category behaviour.
- The sweep runs once at launch, off the main actor where the store requires it, with `orphanGraceSeconds` 60. Do not add a timer, a repeating sweep or a sweep on every foreground.
- `AppCoordinator.swift` is a shared hotspot; T-022 already added the service half in an earlier wave. Keep this diff additive and localized. Do not reformat the file.
- No new egress, analytics or third-party SDK.
