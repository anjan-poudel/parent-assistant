## Description
Settings → Medications first shows the family's existing schedules. The new
`MedicationManageListView` renders one row per `coordinator.medicationEntries`
entry — name, the composed dose line (`DoseLine.compose`), the slot + meal
context, and the purpose caption (`MedicationPurpose.label`) — with an explicit
add control (`settings.meds.add`). Tapping a row opens the existing editor
PRE-FILLED through the shipped T-018 conversion flow (the `draft(from:)` statics
and `editingEntryId` in `MedicationScheduleSettingsView`) — reuse, never rebuild.
The add control opens the same editor in new-entry mode. **The add form never
auto-opens**: the manage list is the screen; the editor is reached only by an
explicit tap. Empty state reuses `settings.meds.empty`. Legacy entries (clock
model) list and edit exactly as stored — no silent conversion (T-018's pin
stands). The Medicine-times card and its one-shot retime note (T-020) remain
reachable on the manage screen. Voice-first flows are untouched. All interactive
elements keep the elderly-fit floor: 44pt minimum targets, 18pt minimum
user-visible type (NFR-MSR-005, FR-MSR-021).

## Acceptance criteria

```gherkin
Feature: Settings shows the family's medication schedules first, not a blank form

  Scenario: The list renders every existing schedule
    Given a household with existing medication schedules, including legacy entries
    When the family opens Settings and then Medications
    Then every schedule is listed with its name, dose line, slot and meal context, and purpose caption
    And legacy entries appear exactly as stored
    And the add form is not open

  Scenario: Tapping a row opens the editor pre-filled
    Given the manage list with an existing schedule
    When the family taps that schedule's row
    Then the editor opens filled from that entry
    And saving edits the same entry (no duplicate is created)

  Scenario: The add control opens a new-entry form
    Given the manage list
    When the family taps the add control
    Then the editor opens in new-entry mode
    And the empty form is not what Settings showed on arrival

  Scenario: A household with no schedules sees the honest empty state
    Given a household with no medication schedules
    When the family opens Settings and then Medications
    Then the existing empty message "No medications scheduled yet" is shown
    And the add form is not open until the add control is tapped

  Scenario: The controls meet the elderly-fit floor (guard)
    Given the manage list's interactive elements
    When they are measured
    Then each has at least a 44pt interaction target
    And user-visible type is at least 18pt
```
