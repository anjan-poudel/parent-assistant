## Description
Add the instruction row to the existing routine editor and present the shared instruction editor for text, image and video. The save goes through the coordinator's single routine seam; the view never reaches the scheduler or the video store. Existing reminder editing, photo visual aids and the sheet structure stay intact.

## Acceptance criteria

```gherkin
Feature: Routine settings instruction editing

  Scenario: A caregiver adds a text instruction to a routine
    Given the routine editor for an entry with no instruction
    When the caregiver chooses text, types a message and saves
    Then the editor sends one text commit through the coordinator
    And the routine row reflects the instruction on return
    And the reminder's title, time and photo are unchanged

  Scenario: Image and video instructions use the shared editor and capture
    Given the routine editor
    When the caregiver chooses an image or records/picks a video
    Then the shared instruction editor is presented with the routine's draft
    And the save is enabled only when the draft resolves
    And a permission problem shows one plain line
    And no Settings deep link or photo-library path is offered

  Scenario: Cancelling changes nothing
    Given the editor with an existing instruction
    When the caregiver cancels after editing
    Then no save seam is called
    And the stored instruction and media are unchanged
    And the previous file still exists

  Scenario: A save failure keeps the editor honest
    Given the coordinator returns ownerNotFound or persistenceFailed
    When the caregiver saves
    Then one plain failure line is shown
    And the editor stays open with the draft intact
    And the previous instruction remains in place

  Scenario: The photo visual-aid flow is untouched
    Given a routine entry with a visual aid and no instruction
    When the photo editor is opened
    Then it behaves exactly as before this feature
    And adding an instruction does not replace or delete the visual aid
```

## Implementation notes
- Follow design §2.10 (C09), §11.3 M (baseline preservation), §11.3 O, §11.3 Q. The current view is small (`ios/ElderlyAssistant/App/RoutineSettingsView.swift`, about 155 lines) and already presents a photo sheet through `coordinator.visualAidStore`; do not restructure it into a navigation stack or a new tab.
- The view may read `coordinator.routineEntries` as it does today and may call `coordinator.saveRoutineInstruction`. It must not hold `RoutineScheduler`, `InstructionVideoStore` or a file manager.
- Reuse `InstructionEditorView` from T-018. The routine-specific part is the row, the sheet and the save call, not a second editor.
- A media draft without pending bytes cannot save; show the editor's disabled state rather than a custom message. A permission problem comes from the capture coordinator as a typed value and maps through `InstructionMessageKey`.
- Do not add a "manage instruction" screen in Settings, a deep link to system Settings, a link field, a photo-library picker or a second visual-aid editor.
- The existing photo flow, refresh key and entry summary behaviour must remain byte-compatible where the design does not require a change. Add the instruction row without reordering existing controls more than necessary.
