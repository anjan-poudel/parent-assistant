## Description
Add the thin image-loading seam used by the card and the editor. It reuses the existing visual-aid image store and its filename validation rather than creating a second image store, and it never opens a photo-library asset. Failures are typed values that the surface can turn into one plain line.

## Acceptance criteria

```gherkin
Feature: Instruction image loading

  Scenario: A stored instruction image loads without touching the library
    Given an owner folder containing a valid JPEG named by the instruction
    When the loader loads that filename
    Then the image is returned
    And no photo-library permission is requested
    And no picker is presented

  Scenario: Traversal or empty filenames are refused before a URL exists
    Given a filename that is empty, absolute, contains a path separator, or escapes the owner folder
    When the loader is asked to load it
    Then it returns invalidFilename
    And no file is read

  Scenario: A missing or undecodable file falls back honestly
    Given a filename that no longer resolves or bytes that are not an image
    When the loader runs
    Then it returns missing or decodeFailed
    And the surface can render the plain unavailable line

  Scenario: An instruction image and a visual aid can coexist for one routine
    Given a routine entry with a visual aid and a separate instruction image
    When both are saved and read back
    Then each file remains in its own store
    And removing the instruction does not delete the visual aid
```

## Implementation notes
- Follow design §4.3 (owner roots), §5.8 (image reuse and the N-1 boundary), §10.3 (image accessibility), §11.3 D (filename guard).
- The loader returns `InstructionImageFailure` with exactly the three design cases. Do not collapse them into one string.
- **N-1 / N-4:** the non-empty and plain-component guard is mandatory. Reuse the existing validation in the visual-aid image path; if that validation is private, extract it inside `InstructionImageLoading.swift` rather than weakening the existing store.
- Instruction images live under the owner's own root and are not visual aids. They must not appear in a notification attachment or the visual-aid array.
- No `Photos`, `PHPhotoLibrary`, `UIImagePickerController` photo-library mode or `PHPicker` access in this file.
- This unit does not create an image editor or picker; T-018 owns the surface and T-022 owns the factory seams.
