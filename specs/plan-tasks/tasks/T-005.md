# T-005: Scanned schedule to slots conversion — pinned hour table

## Metadata
- **Components:** C9 (ScannedSchedule; NEW, beside the label parser)
- **Interfaces:** IF-23 (`ScannedSchedule.slots(from:)`)
- **Wave:** 1

- **Effort:** S
- **Risk:** MEDIUM — a wrong hour mapping would pre-fill a wrong slot; the human save gate still stands between a misread and a binding (FR-MSR-006), but the table is pinned.

## Owned files

- `ios/ElderlyAssistantTests/Services/MedicationScheduler/ScannedScheduleTests.swift` (new)

## Description
Create the pure conversion from a parsed label read to slot candidates, using the pinned hour table (m-3, verified against the parser's emitted-hour union): 8:00 → morning; 12:00/13:00 → afternoon; 19:00/20:00/21:00 → evening; any other emitted hour maps to nothing. Deduplicate with first-occurrence order preserved. The conversion never consults the household mapping (the mapping re-times at arming/display only), never infers a meal relation, and emits slots only — the draft (T-009) applies them under the shipped additive rules, and nothing binds without the human save gate.

## Acceptance criteria

```gherkin
Feature: A scanned schedule proposes slots, nothing more

  Scenario: A label read is converted to slot candidates
    Given a parsed label read emitting the hours 8 and 19
    When the read is converted
    Then the candidates are morning and evening in first-occurrence order
    And the household mapping was not consulted

  Scenario: An unmapped read changes nothing (edge)
    Given a parsed label read emitting only hours outside the pinned table
    When the read is converted
    Then the candidates are empty
    And nothing is proposed
```

## Implementation notes
- The hour table covers the parser's actual emitted-hour union {8, 12, 13, 19, 20, 21} (`MedicationLabelOCR.timeWordHours` :203, `slotHours` :213, `countedDoseHours` :220); no emitted hour is left unmapped.
- Pure function; no I/O; no mapping access; no meal-relation inference.
- Exists beside the parser, not inside it, so the parser file is not touched by this feature.
