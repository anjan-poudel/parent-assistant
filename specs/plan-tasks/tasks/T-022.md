## Owned files
- Extends `ios/ElderlyAssistant/App/AppCoordinator.swift` with the instruction stores, capture coordinator, factories and the two save seams.
- Creates `ios/ElderlyAssistantTests/App/AppCoordinatorInstructionTests.swift` (save and factory half; T-025 extends it).

## Description
Wire the feature into the app's single composition root without giving views a store. The coordinator owns the video store, the capture coordinator and the factories for the picker, recorder and playback controller; it exposes one save entry point per owner kind that delegates to the scheduler or event service and returns the typed result the editor needs.

## Acceptance criteria

```gherkin
Feature: Coordinator instruction composition

  Scenario: Saving a routine instruction goes through the scheduler seam
    Given a saved routine entry and a resolved text commit
    When saveRoutineInstruction runs
    Then RoutineScheduler.setInstruction receives exactly that commit and entry id
    And the coordinator returns the same Result to the caller

  Scenario: Saving an event and its instruction reports the partial outcome
    Given a valid form with an instruction draft
    When saveFreeFormEvent runs
    Then FreeFormEventService.save receives the form and the editing id
    And the outcome returned is the service's outcome, not a Boolean

  Scenario: The capture coordinator is shared and single-flight per editor session
    Given the coordinator's instruction capture factory
    When the routine editor and the event editor each ask for a coordinator
    Then each receives a coordinator bound to its own draft session
    And the shared video store is the one instance the coordinator owns
    And no picker or recorder is created until the editor asks

  Scenario: Factories build the production adapters exactly once per use
    Given the coordinator
    When a picker, recorder or playback controller is requested
    Then the matching production type is returned
    And no network, transcode or photo-library adapter is constructed
    And no playback starts from the factory

  Scenario: Store failures are surfaced, never swallowed
    Given a scheduler seam that returns ownerNotFound
    When saveRoutineInstruction runs
    Then the caller receives failure ownerNotFound
    And the editor remains open with the previous instruction intact
```

## Implementation notes
- Follow design §2.15 (C15 composition), §3.6 (IF-32), §7.1 (shared resources), §7.5 (teardown), §11.3 L (single-file invariants), §11.3 Q.
- The coordinator is the only composition root. Add the video store, the capture coordinator and the factories here; do not add store references to `RoutineSettingsView`, `EventsView`, `InstructionViews` or any child view.
- `saveRoutineInstruction(_:entryId:) -> Result<Void, InstructionWriteError>` delegates to `RoutineScheduler.setInstruction`. `saveFreeFormEvent(_:editing:) -> FreeFormEventSaveOutcome?` delegates to `FreeFormEventService.save`. One entry point each, no duplicate transaction logic.
- The picker and recorder factories return the T-010 adapters; the playback factory returns the T-017 controller with the T-004 adapter. A factory must not start playback, present a picker, request permission or perform IO.
- Keep `AppCoordinator` initialization free of file IO. The video store resolves its base directory lazily; do not force it in `init`.
- Do not add the fired-screen presentation methods, the tap sink or the launch sweep in this unit; T-025 owns those. Do not edit `ContentView`, `VisualAidViews`, `RoutineSettingsView` or `EventsView`.
- `AppCoordinator.swift` is a shared hotspot. Keep the diff additive and localized; do not reformat the file.
- No new egress, cloud call, analytics or third-party SDK.
