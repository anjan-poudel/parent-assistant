## Description
Validate an already-staged video against the configured limits without copying it again. Probing is synchronous and cheap; inspection is async and bounded by `validationTimeoutSeconds` (20 s). Any failure or cancellation discards the staged bytes so a rejected pick never lingers.

## Implementation notes
- Follow design §2.5 (C03), §5.4 (limits and order), §9.1 (20 s bound), §9.2 (async call register), §11.3 E (limit cases).
- The importer is validate-only. The picker or recorder already produced the staged copy through `InstructionVideoStore.stageSynchronously`; this unit must not stage or copy a second time.
- Order: cheap file checks, byte cap, probe, then bounded async inspect. Size is checked before any expensive work.
- The timeout race must cancel the inspection task and then call the store's discard. Do not leave a detached task alive after returning.
- **N-10:** the bound is inclusive at 180 seconds. Round the duration the same way the model does; do not use a strict comparison that rejects a 179.6 s file.
- Cancellation is a normal outcome (`cancelled`), not an error to apologise for. The surface decides not to render a failure line.
- Do not add observability here; the capture coordinator owns the emission once (T-009).
