## Description
Wire the resolution feed: `resolvedScheduleTimes(for:)` resolves a slot entry freshly through C1 (T-001) at arming time; entries with no slot keep the stored mirror (`scheduleTimes`). `createPendingReminders` (:707) consumes the resolved times, and the shipped order — persist the reminder state (:733) before arming the platform alarm (:737–744) — is preserved exactly. An unresolvable slot (typed failure from C1) skips that entry's arming and surfaces as the PII-free `medication_slot_unresolved` event (slot only; the metadata keys are registered at the release gate, T-022). Storage failure keeps the shipped `reminder_persistence_failed` path and arms nothing. Resolution happens at schedule/arming time only — never at fire time (NFR-MSR-010's shape is unchanged).

## Acceptance criteria

```gherkin
Feature: Reminders arm from the resolved exact time, persist first

  Scenario: Default mapping arms the reminder at the mapped clock time
    Given a household with the default mapping (morning 08:00, afternoon 13:00, evening 19:00)
    And an entry with the morning slot, before meal
    When the day's reminders are created for that entry
    Then the reminder is armed for 08:00
    And the acknowledgement window, re-fire schedule and escalation deadline derive from that same 08:00 scheduled time

  Scenario: Persistence precedes alarm arming
    Given a slot entry whose mapping resolves to this morning's time
    When its reminders are created
    Then the reminder state is persisted before the platform alarm is armed
    And the persisted state carries the resolved exact scheduled time

  Scenario: A storage failure blocks the alarm (failure)
    Given a storage write that fails while a reminder is being persisted
    When the scheduler would arm the platform alarm
    Then the alarm is not armed
    And the failure surfaces as an error

  Scenario: An unresolvable slot arms nothing and surfaces (failure)
    Given an entry whose slot cannot be resolved to a determinate hour/minute
    When the day's reminders are created
    Then no reminder is armed for that entry
    And the condition surfaces with the slot only (no name, no dose content)
    And no implicit or guessed clock time is used
```

## Implementation notes
- `resolvedScheduleTimes(for:)` returns the freshly resolved times for slot entries and the stored mirror for legacy entries; the mirror is never rewritten here (D2: the save gate and the mapping re-arm pass are its only writers).
- `medication_slot_unresolved` carries the slot only — no medication name, no quantity (NFR-MSR-002); the observation is declared for the release gate in T-022.
- No change to reminder state shapes, EscalationEngine, or the notification payload here.
