## Description
Wire capture end to end. `captureEvidence(image:context:) -> EvidenceCaptureOutcome` (IF-14) with three paths: `.pendingDose(entryId)` mints the log id at capture (R-1(a)), stores through C5 (T-007) and holds through IF-15 (T-019); `.record(logId:entryId)` (the record surface) stores and attaches to the existing log only; `.declinedNoContext` declines when no context exists — by construction a photo can never create a record. Store work runs off main with the outcome delivered on main; captures are single-flight (one at a time). The fired-dose screens (`MedicationVisualAidViews` / `MedicationVisualAidFireHandler`) gain the photo-as-evidence affordance; the announce line names the bound medication (D11; the presentation already carries `medicationName`, :26/:141/:159). The Meds leaf gains the "Taken today" record-surface section: today's confirmed records with a row-level add-photo action (record-surface naming follows the record convention) plus the IF-24 read seam over the scheduler's taken logs. The unwired PhotoVerifier machinery is not referenced, wired or repurposed (FR-MSR-020); nothing leaves the device (NFR-MSR-003). All new controls meet the 44pt/18pt elderly-fit floor.

## Acceptance criteria

```gherkin
Feature: Photo evidence attaches to a confirmed intake and never creates one

  Scenario: Evidence attaches to a confirmed intake
    Given the elder completed the acknowledgement and confirmation challenge for a medication
    When the elder photographs the medication as evidence
    Then the evidence is attached to the intake record
    And the record exists because the acknowledgement chain completed, not because of the photo

  Scenario: A photo alone never records a dose (misuse guard)
    Given no acknowledgement has been made for a medication
    When only a photo of the medication is captured
    Then no taken record is created
    And the intake still requires the acknowledgement and confirmation sequence

  Scenario: Two medications sharing a slot keep separate evidence (edge)
    Given two entries share the morning slot
    When each confirmed intake receives its evidence
    Then each record carries its own evidence file
    And no capture is shared or borrowed across entries

  Scenario: The announce names the medication (edge)
    Given a capture surface opened for a bound medication
    When the capture is announced
    Then the announce line names that medication
    And it never names a different one
```

## Implementation notes
- No medication photo leaves the device; the capture path has no network symbol.
- Claims stay honest: a store failure is surfaced, never claimed attached (FR-MSR-018); a lost hold (process death) is simply absent — never claimed.
- The camera affordance reuses the shipped scanner/camera plumbing where possible; no new photo-permission flow is introduced.
- "Taken today" renders only durable records; it is a read surface, never a write path to records.
