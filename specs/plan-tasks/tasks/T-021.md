## Description
Teach the existing fired-routine screen to host one instruction and to keep today's screen when there is none. The D6 rule is the crux: the fire time renders only when an instruction is present or the notification said one was expected. A deleted owner becomes a plain notice with Close, never a blank screen or a dead tap. This unit is the sole owner of must-carry finding **N-5** and the paired baseline preservation for NFR-RIE-010.

## Acceptance criteria

```gherkin
Feature: Fired routine instruction screen

  Scenario: An instruction present renders the card and the fire time
    Given Content.reminder with an instruction present and expectsInstruction true
    When the overlay renders
    Then the card state matches the instruction kind
    And the fire time is passed as timeText
    And the footer renders the instruction

  Scenario: A removed instruction keeps the title and time and says it was removed
    Given Content.reminder with instruction nil, expectsInstruction true and a fire date
    When the overlay renders
    Then the card state is removed
    And timeText is passed
    And no empty container or dead control appears

  Scenario: A photo-only firing renders exactly today's screen
    Given Content.reminder with instruction nil and expectsInstruction false
    When the overlay renders
    Then timeText is nil
    And the instruction card is EmptyView
    And the footer is EmptyView
    And the photo screen is unchanged

  Scenario: A deleted owner renders the notice with Close
    Given Content.unavailable
    When the overlay renders
    Then the shared screen shows instruction.reminderUnavailable
    And aids is empty
    And the footer is EmptyView
    And Close dismisses
    And no title or time is claimed

  Scenario: The overlay resolves copy itself and holds no service
    Given the overlay source
    When it is inspected
    Then it resolves instruction.reminderUnavailable through the localisation helper
    And it reaches no store, scheduler or coordinator method directly

  Scenario: The time format uses the shared short-time formatter
    Given a fire date
    When the overlay composes the time line
    Then it uses LocaleFormatters.shortTime with the active locale
    And it does not build a date format inline
```

## Implementation notes
- **N-5 (must-carry):** the D6 gate is stated once in design §4.10 and applied at the composition seam in §2.15.4. `timeText` is non-nil only when `instruction?.isPresent == true || expectsInstruction`. `.unavailable` carries no `firedAt` and therefore can never render a time.
- The baseline case is exact: a photo-only foreground firing (`instruction == nil`, `expectsInstruction == false`) passes `timeText == nil`, the card is `.none` (`EmptyView`) and the footer is `EmptyView`. The rendered screen is today's. Compare against the shipping shape in `VisualAidViews.swift` around the current fired-screen lines; do not reformat or restyle the existing photo screen.
- `FiredRoutineVisualAids.Content` changes from `.reminder(title:aids:)` to `.reminder(title:aids:instruction:expectsInstruction:firedAt:)` and gains `.unavailable`, exactly as design §4.11. `ContentView` passes `coordinator.firedRoutineVisualAids` as it does today.
- The overlay is a view: it resolves `instruction.reminderUnavailable` itself. Do not put copy in a service.
- The deleted-owner notice reuses `ReminderVisualAidScreen` with `aids: []`, the notice title, an `EmptyView` footer and Close. No title or time is claimed because none can be resolved.
- `InstructionSurfaceTests.swift` was created by T-018; this is a later-wave extension. Keep T-018's cases intact.
- Do not add a notification category, action, attachment, analytics or a new screen.
