## Description
Turn the value layer into the write algebra the editors and services share, and collapse every stored shape into one honest display state. The draft must express "keep", "set text", "set media with or without caption", and "remove"; the display state must distinguish "no instruction", "instruction present but unsupported", and "instruction was removed".

## Acceptance criteria

```gherkin
Feature: Instruction draft and display state

  Scenario: A media draft without pending bytes is unresolved
    Given a selected image or video kind with a caption but no pending media and no stored filename
    When resolvedWrite is computed
    Then it is nil
    And the editor can state that the instruction is not ready to save

  Scenario: Removing an instruction is explicit, not an empty text value
    Given an owner with an existing instruction
    When the draft is the remove value
    Then resolvedWrite is InstructionWrite.remove
    And no empty text instruction is written

  Scenario Outline: Stored shapes collapse to one display state
    Given a stored instruction of <kind> with <fields>
    When InstructionPresentation.state(for:isExpected:) runs
    Then the state is <state>

    Examples:
      | kind    | fields                          | state                 |
      | text    | non-blank text                  | text(text)            |
      | image   | filename and caption            | image(filename,caption) |
      | video   | filename and caption            | video(filename,caption) |
      | text    | blank text                      | none                  |
      | video   | video never playable on device  | unsupported(text)     |
      | absent  | owner expects an instruction    | removed               |
      | absent  | owner never had an instruction  | none                  |

  Scenario: An unsupported instruction is never presented as a control that cannot work
    Given a kind the surface cannot render
    When the state is computed
    Then the state is unsupported and carries the saved text when there is one
    And no play or open control is produced
```

## Implementation notes
- Follow design §3.5 (write algebra and truth table), §4.6 (tolerant-decode table), §4.9 (display state to surface), §4.4 (owner semantics).
- `InstructionDraft` values are the editor's vocabulary. It must be possible to express "set the caption without replacing the media" only where the design allows it; do not add a mutation the design does not name.
- `InstructionPendingMedia` wraps `UIImage` or `AcceptedInstructionVideo` (both available after T-002). Keep it `Equatable` as design P-7 requires; compare accepted-video values, not bytes.
- `InstructionDisplayState` has exactly the six cases in design §4.9. `.unavailable` is deliberately not a display state; it is the fired-screen content case owned by T-021.
- `InstructionPresentation.state(for:isExpected:)` is pure and static. It must never read a store, a file or a locale.
- Do not add `InstructionMessageKey` here; T-007 adds it and the copy map once all error types exist.
- `Instruction.swift` was created in T-001; this is a later-wave extension of the same file. Keep T-001's declarations unchanged.
