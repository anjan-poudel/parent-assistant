## Description
Add the routine write seam that the settings editor calls. It performs the design's ordered transaction: bytes become durable before the index names them, the new index moves before old bytes are deleted, and every failure leaves the previous instruction and its media intact. It also teaches the scheduler the strict read and deletes media when an entry is deleted. This unit owns must-carry finding **OI-1**.

## Acceptance criteria

```gherkin

  Scenario: A successful set is ordered and reschedules once
    Given an existing routine entry and a validated pending video
    When setInstruction runs

    And the window is regenerated once with hadInstruction true

  Scenario: A persistence failure does not orphan the new bytes
    Given the store refuses the new payload after the media commit
```

## Implementation notes
- **OI-1 (review-l2 Condition):** `setInstruction(_:entryId:) -> Result<Void, InstructionWriteError>` is the IF-22 contract. Keep the design's error labels exactly; do not reintroduce a `Bool`. `InstructionWriteError` is declared in this shared file (implementation pin P-4) because it is the C11/C13 write seam's error and is visible to the event service after this wave.
- **M-4:** `entriesIfReadable()` delegates to `RoutineStore.loadEntriesIfReadable()`. It must not be implemented as `loadEntries()` plus a flag, and it must never convert nil to an empty array.
- **Ordered transaction (§5.6):** commit bytes, persist the index, then delete the old file. A failure after commit but before persist must delete the newly committed file or adopt it; never leave bytes no index names. A failure after persist leaves the new file and reports success; the old file is best-effort.
- **FR-RIE-015 / N-9:** `regenerateWindow` passes `hadInstruction: entry.instruction?.isPresent == true` for every occurrence it arms. The reminder must arm and fire with or without an instruction.
- **FR-RIE-021/023:** keep scoped cancels only. Do not add acknowledgement, escalation, timers, categories or actions.
- Emit `entry_instruction_updated` once on a real change only. Do not emit on a no-op or a failure.
- `InstructionMessageKey.forWrite` maps `ownerNotFound`, `unresolvedPayload`, `mediaWriteFailed` and `persistenceFailed` to the design's plain keys. Add it in the same file T-007 created.
- Do not edit `RoutineStore.swift` (T-011 owns it) or `RoutineEntry.swift`.
