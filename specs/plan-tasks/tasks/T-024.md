## Description
Add the instruction row to the free-form event editor and render the saved instruction on the event detail. An event with no instruction renders nothing extra, so the existing detail is unchanged. The save goes through the coordinator's event seam and reports a partial outcome honestly.

## Acceptance criteria

```gherkin
Feature: Event instruction editing

  Scenario: A caregiver adds an instruction while creating or editing an event
    Given the event form with no instruction draft
    When the caregiver attaches a text, image or video instruction and saves
    Then the coordinator's saveFreeFormEvent receives the form with one draft
    And the event is saved before the instruction is written
    And the detail shows the instruction after returning

  Scenario: An event with no instruction renders exactly today's detail
    Given an event with a photo and no instruction
    When the detail is shown
    Then the instruction state is none and renders nothing
    And the event title, time, address and photo are unchanged

  Scenario: A partial save is reported as partial
    Given the event saves but the instruction write fails
    When the save returns the partial outcome
    Then the view shows one plain line about the instruction
    And the event remains saved and editable
    And no success claim is made for the instruction

  Scenario: Cancelling or deleting an event tears down its instruction
    Given an event with an instruction
    When the caregiver cancels editing
    Then nothing is written
    When the caregiver deletes the event
    Then the event deletion proceeds through the existing path
    And its instruction media is torn down
    And the detail returns to the list without a dead screen

  Scenario: No link, URL or photo-library instruction path is offered
    Given the event editor
    When the instruction choices are shown
    Then the choices are text, image and video capture only
    And there is no URL field, YouTube link, share sheet or photo-library-only path
```

## Implementation notes
- Follow design §2.10 (C10), §4.5 (form and extras), §4.9–§4.10 (display state), §11.3 M and Q.
- Reuse `InstructionEditorView` and `InstructionCardView` from T-018. The event-specific work is the form row, the save call and the detail card.
- The form lives in `FreeFormEventService.swift` (see implementation pin P-1); the view owns presentation only. Do not create `FreeFormEventDraft.swift`.
- A partial outcome is `instructionSaved`, not total success and not total failure. The plain line must name the instruction only; never show an error code.
- Event notifications do not gain `had_instruction` (design OI-8). Do not change the event notification payload or add a tap branch.
- The existing event photo, address, recurrence and Google reconcile behaviour must remain unchanged. This is a shared file; keep the diff additive and localized.
- No URL field, link playback, YouTube, transcode, trimming, share sheet or photo-library-only picker.
