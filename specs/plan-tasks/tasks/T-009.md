## Description
Own the one-at-a-time capture state machine shared by the routine and event editors: idle, picking, recording, validating, ready, failed. It enforces camera-before-microphone (must-carry **M-1**), prevents a second pick or record while one is in flight, consumes an accepted video exactly once, and discards staged media on every exit that does not save.

## Acceptance criteria

```gherkin

  Scenario: A second pick or record is refused while one is in flight
    Given the coordinator is picking or recording

    When record is called
    Then the state is failed with permissionProblem
    And the microphone request count is zero
    And no recorder is presented

  Scenario: A validated video becomes ready and is consumed once
    Given a picker or recorder produced a staged file that validates
    When the importer accepts it
    Then the state is ready with the accepted video
    And consumeAccepted returns it once
    And a second consume returns nil

  Scenario: Cancelling or failing discards staged bytes
    Given a staged file exists while validating
    When the person cancels or validation fails
    Then the staged file is discarded through the store
    And the state is idle or failed as appropriate
    And no accepted video is handed to an editor

  Scenario: The coordinator owns no player and no autoplay
    Given a video becomes ready
    When the state changes to ready
    Then no playback controller is created
    And no audio session is activated
```

## Implementation notes
- Follow design §2.4 (C04), §7.2–§7.4 (isolation, single flight, teardown), §11.3 J (capture contract), §11.3 R (permission order).
- `@MainActor` throughout. All picker/recorder/importer/store collaborators are injected protocols or closures so tests run without a device.
- The state enum is exactly idle, picking, recording, validating, ready, failed. `permissionProblem` is carried on the failed state (or an equally explicit typed payload) and is never a bare string.
- **M-1:** camera before microphone, with a denial short-circuit. This is the authoritative check; T-006's unit tests the seam in isolation.
- `consumeAccepted()` clears the accepted value before returning it, so a double-tap cannot save the same draft twice. `discardAccepted()` discards staged bytes through the store.
- Exactly one `instruction_capture_permission` event per attempt, and one import outcome per attempt. Do not emit on every status read.
- Do not create a player, a preview, an autoplay path, a photo-library picker or a transcode step.
- Keep the picker/recorder presentation behind the protocols; T-010 supplies the production adapters.
