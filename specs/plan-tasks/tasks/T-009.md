## Description
Extend the shipped draft type with the slot model: `scheduleMode` (clock rows vs slot rows, per draft), slot rows (slot + meal relation + quantity + unit), `storedRows` producing the save request rows (T-017 consumes them), `applyScan` applying the T-005 conversion — the label's stated schedule replaces the slot rows exactly as the shipped rule replaces times, text still pre-fills blank fields only, an empty read still changes nothing — and `applySlotPreselection` for the edit-existing flow (exact-equality preselection; no fuzzy matching). `canSave` stays name-only and `storedTimes` stays `[.hour, .minute]` only. No rule is relaxed; no inference is added.

## Acceptance criteria

```gherkin
Feature: The draft keeps its rules while the slot model arrives

  Scenario: The existing draft rules are not relaxed
    Given a scanned label whose stated schedule differs from the current form values
    When the scan is applied to the draft
    Then the label's stated schedule wins over the form's values
    And text only fills blank fields
    And an empty read changes nothing

  Scenario: A scan proposes slot rows under the same rules
    Given a draft in slot mode and a parsed read converting to morning and evening
    When the scan is applied
    Then the slot rows carry morning and evening in first-occurrence order
    And the meal relation was not inferred

  Scenario: An unmapped scan read changes nothing (edge)
    Given a draft with existing slot rows
    When an unmapped read is applied
    Then the rows are unchanged

  Scenario: An entry without a name cannot be saved (failure)
    Given a draft with slot rows but no medication name
    When canSave is asked
    Then the save is rejected
    And no entry is persisted
```
