## Description
Add the in-memory evidence hold and its finalize integration.
**R-1 pin (a) — chosen and stated:** the coordinator mints the log id at capture time (T-021, `.pendingDose` path), the store names the file by it, and `finalizeAcknowledgement` **uses that held id for the log it writes** — the shipped `MedicationAdherenceLog(id: UUID(), …)` mint (:461) becomes `heldLogId ?? UUID()`. The `<logId>.jpg` scheme therefore stays true everywhere, including pending captures. IF-15 is realized as `holdPendingEvidence(logId:fileName:for:)` (the fileName-only shape could not carry the id finalize must write; this realization is the R-1(a) resolution).
**Attach at finalize.** The held file's name is set as `evidencePhotoFileName` on the log before the single persist; a persist failure returns the shipped `.reminderPersistenceFailed` and deletes the held file (no orphan), and `intakeRecorded` does not fire (it follows the write — T-016).
**R-3 — late-hold rule, pinned:** a hold registered when no un-finalized reminder exists for the entry is **cleared at registration** — the stored file is deleted and no hold is registered; the record stays honestly evidence-free (never claimed attached).
**Other paths.** Deny / re-enter clears the hold (file deleted); re-capture replaces (prior file deleted); process death loses the hold and with it any claim (honest loss, by design). `attachEvidence(fileName:toLog:)` serves the record surface: it attaches only to an existing log and never creates one.

## Acceptance criteria

```gherkin
Feature: Evidence attaches to a confirmed intake, or stays honestly absent

  Scenario: The held capture is the record's evidence under one identity (R-1(a))
    Given a capture stored and held for an entry with an un-finalized reminder
    When the acknowledgement finalizes
    Then the written adherence log's id equals the held log id
    And the record's evidence photo file name equals the stored bare file name
    And the name equals the log id everywhere

  Scenario: A late hold is cleared at registration (R-3)
    Given a capture whose store completes after the acknowledgement chain finalized
    When the hold registers for that entry
    Then no un-finalized reminder exists for the entry
    And the hold is cleared and the stored file is deleted
    And the record stays honestly evidence-free

  Scenario: A persist failure cleans up and claims nothing (failure)
    Given a held capture and a failing adherence-log write
    When the acknowledgement finalizes
    Then the result is the shipped persistence failure
    And the held file is deleted (no orphan)
    And intakeRecorded does not fire

  Scenario: A photo alone never records a dose (misuse guard)
    Given no acknowledgement has been made for a medication
    When only a photo of the medication is captured
    Then no taken record is created
    And the intake still requires the acknowledgement and confirmation sequence
```
