## Description
Provide the only sanctioned way this feature writes diagnostics: typed, fire-and-forget emitters with fixed event names and closed field vocabularies, plus the pure mapping from every typed failure to a localisation key. There is no free-text logging seam, and no user content may enter either surface.

## Acceptance criteria

```gherkin
Feature: Instruction observability and plain failure copy

  Scenario: Every event is emitted with its fixed name and closed fields
    Given a typed observability emitter for media import, delete, availability, playback, image load, capture permission or orphan purge
    When the emitter is called
    Then the event name is one of the seven catalogue names
    And every field value comes from a closed vocabulary or a count
    And no text, caption, filename, URL, person name or event title is present

  Scenario: Unsupported catalogue fields are impossible to pass
    Given the typed emitter signatures
    When a caller tries to attach free-form text
    Then the code does not compile
    And no escape hatch such as a string dictionary exists

  Scenario Outline: Each failure maps to one stable copy key
    Given the failure <failure>
    When InstructionMessageKey maps it
    Then the key is <key>
    And the key exists in both languages

    Examples:
      | failure                             | key                         |
      | import unreadableSource             | instruction.import.failed   |
      | import unsupportedFormat            | instruction.import.failed   |
      | import tooLong                      | instruction.import.tooLong  |
      | import tooLarge                     | instruction.import.tooLarge |
      | import validationTimedOut           | instruction.import.failed   |
      | import writeFailed                  | instruction.import.failed   |
      | import cancelled                    | instruction.import.cancelled |
      | playback unsupported                | instruction.video.unavailable |
      | playback playerFailed               | instruction.video.unavailable |
      | playback interrupted                | instruction.video.unavailable |
      | playback timedOut                   | instruction.video.unavailable |
      | image invalidFilename               | instruction.image.unavailable |
      | permission cameraDenied             | instruction.permission.camera |
      | permission microphoneDenied         | instruction.permission.microphone |
```

## Implementation notes
- Follow design §6.2 (exact event catalogue), §6.3 (release-log gate and honest limits), §10.3 (copy table), §11.3 N (localisation).
- Event names are exactly: `instruction_media_import`, `instruction_media_delete`, `instruction_media_availability`, `instruction_playback`, `instruction_image_load`, `instruction_capture_permission`, `instruction_orphan_purge`.
- The emitter protocol must be `Sendable` and fire-and-forget. Production writes through the existing logging facility. Do not add a new log sink or change the allow-list.
- **NFR-RIE-004:** no PII. No titles, captions, filenames, paths, URLs or identifiers beyond counts and closed kinds. The release gate registration for these roots is T-026; this unit must be clean before that gate is added.
- Copy keys must be plain-language keys, never error codes or internal type names in the elder-facing string.
- `InstructionMessageKey.forWrite` is deliberately absent here. T-013 adds it in the same file after `InstructionWriteError` exists, avoiding a forward reference.
- Do not add `InstructionFeatureRoots` or edit the release script; T-026 owns the gate.
