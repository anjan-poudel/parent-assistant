## Description
Replace the save plumbing with the slot-model API. `MedicationSaveRequest` carries the draft's rows; the coordinator adds one `MedicationEntry` per slot row (N rows to N entries, D1), writes each entry's `scheduleTimes` as the D2 resolved-time mirror (composed from the row's slot through C1), composes `doseDescription` through C2 (T-002), and persists through the shipped load path. The **duplicate rule (m-2)** keeps the shipped expression exactly — exact name equality plus effective-time intersection — over effective times: slot rows contribute the slot's resolved time (their mirror), so a mixed legacy/slot pair compares resolved-vs-stored and still flags; entries created earlier in the same save participate; `updateMedication` excludes self; a corrupt mapping or an empty mirror does not flag. `removeMedication` gains the evidence cascade (`MedicationEvidenceStore.deleteAll(for:)`, T-007 — fail-soft). `photoVerificationEnabled: false` stays at the construction sites. The shipped `addMedication(name:times:purpose:strength:photo:)` path remains for legacy rows.

## Acceptance criteria

```gherkin
Feature: Saving slot rows creates one entry per dose, with the shipped duplicate guard

  Scenario: N dose rows create N entries
    Given a save request with two slot rows (morning, evening)
    When the save completes
    Then two entries exist
    And each entry carries its own slot and its resolved-time mirror

  Scenario: A mixed legacy and slot duplicate is flagged (edge)
    Given an existing legacy entry for "Amlodipine" at 08:00
    When a new slot row for "Amlodipine" resolves to 08:00
    Then the duplicate rule flags the pair on exact name equality and time intersection

  Scenario: A corrupt mapping does not produce a false duplicate (edge)
    Given an existing entry and an empty or unresolvable mirror on the new row
    When the duplicate rule runs
    Then it does not flag

  Scenario: An entry without a name cannot be saved (failure)
    Given a save request without a medication name
    When the save is attempted
    Then the save is rejected
    And no entry is persisted

  Scenario: Removing a medication cascades evidence deletion (edge)
    Given an entry with stored evidence files
    When the entry is removed
    Then the evidence files are removed fail-soft
    And the removal does not fail on absent files
```
