## Description
Own the policy around playback: a 0.6 second preflight bound, a 10 second ready watchdog, one failure line, a single close path and a guarantee that late adapter events after close are ignored. The controller owns both timers; the adapter owns neither. Playback never starts until the person asks for it.

## Acceptance criteria

```gherkin
Feature: Instruction playback control

  Scenario: Playback starts only on an explicit start
    Given a video instruction on screen
    When the controller is created
    Then no preflight, no player and no event occurs
    When start is called
    Then preflight is attempted once
    And a passed preflight proceeds toward ready

  Scenario: A preflight that never answers is bounded
    Given an adapter that never reports preflight
    When start is called and 0.6 seconds elapse
    Then the state is failed with unsupported
    And the surface shows one fallback line
    And close is safe to call

  Scenario: A ready signal that never arrives is not the same as a failure
    Given preflight passed and no ready event
    When 10 seconds elapse
    Then the state is failed with timedOut
    And the failure detection path was not treated as a failure before the watchdog
    And exactly one instruction_playback event records the timeout

  Scenario: A late event after close is ignored
    Given the controller is closed
    When the adapter emits ready, finished or failed
    Then the state does not change
    And no event is emitted
    And no timer remains scheduled

  Scenario: Finished closes cleanly and does not loop
    Given playback is ready
    When the adapter emits finished
    Then the state is finished once
    And playback does not restart
    And close releases the adapter

  Scenario: Close pauses before release
    Given the adapter is playing
    When close is called
    Then the adapter receives dismiss
    And the controller cancels both deadlines
    And the URL is not retained after close
```

## Implementation notes
- Follow design §2.8 (C06), §3.6 (IF-20), §8.1 (responsiveness budgets), §9.1 (`preflightTimeoutSeconds` 0.6, `readyWatchdogSeconds` 10), §11.3 I.
- `@MainActor`. Inject a deadline factory so tests use `ManualDeadline` instead of sleeping. No wall-clock sleeps in tests.
- Timers are the controller's alone. The adapter must remain timer-free; a source scan can assert that.
- The 10 second watchdog is a **responsiveness** bound, not failure detection. A failed item is detected by the adapter's failure observation; do not label a slow ready as a failure before the watchdog.
- Emit `instruction_playback` once per terminal outcome with the closed outcome vocabulary. Do not log the URL.
- Close: cancel deadlines, ask the adapter to dismiss (which pauses before releasing), drop the URL, ignore all later events. Close is idempotent.
- No autoplay, no replay loop, no retry, no background playback, no audio session manipulation beyond what the adapter does.
- `InstructionPlayback.swift` was created in T-004; this is a later-wave extension. Keep T-004's public event and failure declarations unchanged.
