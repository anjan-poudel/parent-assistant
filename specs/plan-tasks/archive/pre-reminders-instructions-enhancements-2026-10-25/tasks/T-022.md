## Description
Close the feature with the required integration evidence and the release gates. The four required integration tests (NFR-MSR-008): (1) persistence-before-arm ordering on the slot path (call-order witness through the real scheduler seam); (2) process-kill re-arm — an outstanding unacknowledged reminder from a fresh scheduler instance re-fires within its unexpired window and a future dose stays future; (3) LLM independence — a source-inspecting guard (the `PinnedSurfaceGuardTests` precedent) asserting the medication unit files reference no LLM/router/interpreter symbols; (4) legacy-payload migration round trip with no field loss (the T-003 boundary). Release gates (NFR-MSR-009): register the new medication source paths in the log-safety gate's required-file coverage, declare every new PII-free metadata key (`medication_slot_unresolved`, `medication_retime_refused`, the acknowledgement observations, the honest push error code) in the shipped allow-list (`LogSanitiser.swift`), and run `ios/tools/check-release-log-safety.sh` to green. Confirmation checks: the pinned Devanagari regression suite passes unchanged (NFR-MSR-007, never "fixed"); copy resolves in both locales (NFR-MSR-009, from T-012). **Claim audit (FR-MSR-018):** sweep surfaces, logs and tests for delivery-dependent claims — nothing describes the push transport as delivering; delivery-dependent statements carry the inherited-tracked-work label; no surface claims a photo was attached when it was not. Then the single full-suite run against the documented pre-existing baseline.

## Acceptance criteria

```gherkin
Feature: The revamped paths keep the safety invariants end to end

  Scenario: Kill before acknowledgement — re-fire within the unexpired window
    Given an outstanding, unacknowledged reminder whose escalation window has not yet expired
    When the app process is killed and relaunched
    Then the reminder re-fires on launch
    And the escalation resumes from the remaining window time
    And a dose whose scheduled time has not yet arrived stays future

  Scenario: Persistence precedes alarm arming
    Given a slot entry whose mapping resolves to this morning's time
    When its reminders are created
    Then the reminder state is persisted before the platform alarm is armed
    And the persisted state carries the resolved exact scheduled time

  Scenario: The medication unit is LLM-independent (guard)
    Given the medication unit's source files
    When their symbols are inspected
    Then no LLM, brain or interpreter symbol is referenced
    And the guard fails loudly if one is added

  Scenario: No surface claims a delivery that did not happen (audit)
    Given every user-visible surface, log line and test statement about delivery
    When the claim audit completes
    Then none describes the push transport as delivering
    And delivery-dependent statements are labelled as inherited tracked work
```
