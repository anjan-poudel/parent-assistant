## Decisions made during implementation

- **Task IDs are T-080–T-089, not T-063+.** The brief assumed T-063 was free; it is not. TG-11 holds T-061–T-068 and TG-12 holds T-069–T-079, both authored in their own worktrees with their own committed task files. Renumbering another group's files to fit a plan would have been the wrong resolution, so TG-13 starts at T-080 and the reservation is stated in `plan.md`, `tasks/index.md`, the group index and T-080's Origin line. Commit message therefore reads `[TG-13] Environment robustness benchmark design doc + task group (T-080–T-089)`.
- **Counts were recounted from disk, not propagated.** `plan.md`'s Summary now reads 11 groups in this checkout, 59 parent tasks across 70 IDs (T-001–T-060 + T-080–T-089), with T-061–T-079 reserved by the two in-flight groups; the Task Group Summary total row was corrected to 59 and the TG-13 row added. No task ID was renamed or reused.
- **The benchmark reports STT WER but does not gate on it.** The project has no absolute WER threshold for this pipeline and its held-out STT WER is ~59–64% (`tools/train/src/train_finetune.py:89-93`); a gate on an absolute number would be theatre. WER is reported per cell with a > 1.5× clean flag for attribution. The ship gates are the intent-level and safety metrics, which do have thresholds already set in `config.yaml:56-69`.
- **Every threshold is anchored to an existing project constant, not invented.** The +15 dB 3-point band is `max_gap_vs_gemini: 0.03`; the +5 dB band is TG-11's categorical band; `emergency_recall 1.00`, `side_effect_precision 0.97`, `abstention_precision 0.90` and `contact_f1`/`time_f1` 0.90 are the shipped gate block; the device latency gate is T-038's p50 1000 / p95 2000 ms; the 0.7 in the `confident_error_rate` definition is `IntentRouter`'s `acceptThreshold`. The one new number is the new exit code `3 = SKIPPED`.
- **Accuracy is not gated below the training band.** The only augmentation the project has is white noise at SNR 3–15 dB (`tools/train/src/dataset.py:26-29`), so +15 and +5 dB get accuracy bands and 0 / −5 dB get a **fail-safe clause only** (confident errors ≤ abstentions), which is the same reasoning TG-11 applies at its 3 dB floor. Gating accuracy at −5 dB would measure the fixture.
- **The frozen six-column `eval/results.csv` was not touched (T-084's first draft implied otherwise).** Per-cell evidence goes to a **new** `eval/env/results.csv` with its own schema, plus an additive `--manifest-out` JSONL for metrics the six columns have no room for. The T-038 ledger's schema and revision-label convention are consumed as-is.
- **The accent/voice axis is declared as an enabling condition, not printed as a cell.** One voice exists and it is Hindi (`config.yaml:23`), so a per-voice gate would be vacuous. T-080 was extended (Description paragraph, Gherkin scenario, DoD bullet) to determine the rendering voice's licence per voice, because that determination is also what makes the axis real.
- **The 46-cell figure and the 16,800-render figure are the same arithmetic.** 1 clean reference at n=800 + 5 three-point cells at n=800 + 40 five-point/fail-safe cells at n=300 = 16,800. The group index's earlier "~16,500" (carried from a pre-final draft) was reconciled to 16,800 in the index and in T-088; T-081/T-084/T-088 all cite the design doc's §3.6/§3.7 rather than restating a number.
- **The honest limit is in the group index, not only in the design doc.** "A synthetic transport is not a room" and "a negative result is a deliverable" are stated where a reader of the task tree will see them, because the most likely failure mode of this group is a green-looking number that is not evidence.
- **Risks continue the existing list.** `plan.md` items 32 (benchmark invalid while looking green: licence / transport / power) and 33 (a gate that never failed; the pooling hazard) were appended, not inserted; the "No new security BLOCKERs are introduced by TG-13" paragraph follows the existing pattern.
- **Cross-references, not edits.** TG-11's design doc, T-061–T-068, T-064/T-066/T-068 and TG-12's T-074 are referenced by path and never modified; the only files this group writes are its own four Markdown surfaces. TG-11's and TG-12's worktrees are running concurrently and their files were not touched.

## Open questions (carried into the design doc and the task files, not silently resolved)

- **OQ-1** — which licence-clean voice renders the fixtures; T-080 determines it per voice, and until then the supply is measurement-use-only if the shipped voice's non-commercial basis is not recorded explicitly.
- **OQ-2** — whether the accent axis becomes real (needs ≥ 2 verified Nepali-capable voices plus a product-side decision); it stays a declared gap until both happen.
- **OQ-3** — whether the CPU whisper.cpp decode is a fair proxy for the device's WhisperKit path (it is not); the tiers stay separate and the divergence is a finding.
- **OQ-4** — whether `command_correct` needs a per-path breakdown once TG-12's cascade-default flip lands; T-084 should leave room for a `path` column rather than assuming it away.
- **OQ-5** — the CI tier's minute budget, derived from T-082's measured seconds-per-render; the design deliberately names no cap before the measurement exists.
- **OQ-6** — whether a real-room tier is ever built; it would be a consent-bearing acquisition with its own privacy basis, and this design leaves the door open and the claim closed.
- **Carried, not resolved here** — the shipped piper voice's non-commercial licence is also the licence under which the STT-noise *training* corpus is rendered (`stt_noise.py:30-48`). That is a product and TG-11 [T-066] question, reported with evidence in design doc §5.1 and routed rather than decided by this group.
- **Stale figure outside this task's scope** — the TG-13 group index's effort estimate (26–42 days realistic) is an authoring estimate, not a measured one; if T-080's licence round-trips or T-086's device availability turn out worse than assumed, the group index is the right place to revise it, and this task did not invent a smaller range for it.
