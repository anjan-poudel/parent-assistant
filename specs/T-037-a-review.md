## Findings

- [MINOR] **Gate-off builds still construct the encoder object.** `AppCoordinator.swift:2189` — `if preferredLocal === intentEncoderInterpreter {` accesses the lazy var unconditionally; in a non-`INTENT_ENCODER` build the lazy initializer therefore runs, contradicting the explicit claim at `AppCoordinator.swift:1074-1075` and `IntentEncoderFeature.swift:11-13`. Behaviour is otherwise preserved (no weights load, no observer, no event, no chain change), so this is inert allocation, but the documented invariant is false. Fix: compare against `offeredEncoder` or nest the emission under `IntentEncoderFeature.isEnabled`.
- [MAJOR] **The timeout clock covers model load, not just the forward pass** (contract F-1 detection is `forward_pass_exceeds_local_leg_budget`). The timer is armed at `IntentEncoderInterpreter.swift:293` before the inference block, and `runnerForPrediction` loads the 118 MB graph inside that same window (`:308, 340-382`). With the shipped 2.0 s budget, the first interpret after launch or after every memory-pressure unload can time out while a successful load is still in progress; the late success is then discarded, reporting a spurious `inference_timeout` and escalating to cloud or re-prompting. The stub-model tests cannot catch this because stub loads are instant. Not safety-affecting (fail-soft ladder) and unreachable in any shipping configuration today, but it should be fixed before the encoder is enabled: exclude load from the timed section (resolve the runner first) or add a separate configurable load budget.
- [MINOR] **Committed personal absolute path.** `ModelCatalog.swift:230` and `:819` hardcode `file:///<operator-home>/.local/share/elderly-ai/t033-spike/…` (also in `specs/T-037-a-notes.md:85`). It leaks a first-party username into source and can never resolve on another machine or device. Fix: drop the URL to nil/placeholder or derive it from an environment/test hook.
- [MINOR] **Wrong provenance pointer for the spike label order.** `IntentEncoderSchema.swift:167-169` says the label order is "reproduced in `tools/train-intent/docs/t033-evidence/C3-coreml-report.json`"; that JSON has no `intents`/`tags` keys. The order is genuinely correct (matches the training `meta.json`), and logit-order misalignment is a silently-wrong-action class of bug, so the in-repo citation should be fixable: cite the meta.json or commit the label list into the evidence directory.
- [MINOR] **Calibration temperature has no mechanism anywhere in the runtime.** The contract requires `calibration_temperature` (meta.json required key, `applied_in: interpreter_code`, divide-then-softmax); `IntentEncoderManifest` has no temperature field and `argmaxSoftmax` applies plain softmax (`IntentEncoderInterpreter.swift:742-759`). Safe for the uncalibrated T-033 spike (implicit 1.0), but the notes' "T-035 contract folded in" list omits this gap; it must land before a T-036 artifact is wired or the 0.4/0.7 band policy runs on uncalibrated confidence. Related: contract inputs are int64 while the implementation is int32 — the compiled artifact's `metadata.json` says Int32 (1 × 1...64), so the runner is right for the only existing artifact; T-036's export must reconcile with the contract.
- [MINOR] **Documented I-1 deferrals leave latent contract non-conformances.** `.app` maps verbatim to `requestedApp` rather than the closed-vocabulary projection, and `contact` is not clitic-trimmed (`IntentEncoderInterpreter.swift:475-503`). Unreachable with the spike manifest and explicitly deferred to T-037's integration item I-1, so acceptable here — but must land before any schema-v2 manifest is used.
- [MINOR] Shared install-path change applies beyond the new kind: `ModelStore.swift:266` creates the destination parent for all encodes; in an anomalous ordering (encoder installed before its Whisper model) the previously-failing move now succeeds, leaving an orphan encoder dir. Benign in normal operation; noted for completeness.
