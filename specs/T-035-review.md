## Findings

- [MAJOR] **Cache-hit band claim contradicts shipped code.** Design §9 "Cache interaction" says "the cache hit still goes through `bandChecked` and tier-1 confirmation". `IntentRouter.interpret` returns cached commands directly at `IntentRouter.swift:140-144`, before any `bandChecked` call (call sites are `:150, :208, :278, :302, :341`). The safety conclusion still holds for the reasons the design actually cites (cache writes happen only post-confirmation; `emergency`/`ack_med` are non-cacheable at `IntentCommandCache.swift:55-57`; tier-1 confirmation always fires), and the criterion "no new threshold bypassing bandChecked" is unaffected — but this sentence, and the adjacent "`bandChecked` is the only place the bands are applied", overstate shipped behaviour (`CommandRouter.swift:1081-1085` independently applies the 0.7 threshold to interpreter outputs). Fix: state that cache hits bypass `bandChecked` but remain subject to tier-1 confirmation, and qualify the "only place" claim to `IntentRouter`'s paths.
- [MINOR] **Emergency phrase count is wrong.** §11 says "16 phrases (…:1403-1408)"; `CommandRouter.swift:1403-1408` contains 17 entries (7 English + 10 Nepali). The cited range is right; the count should be 17.
- [MINOR] **Head-size figure conflated with T-033's.** §3.5 says the shipped intent+slot heads "are 0.2 M params". As specified (`Linear(384,12)` + `Linear(384,13)`), they are ~9.6k params (~0.01M). The 0.2M (measured 170,940) is T-033's excluded `bert.pooler` + `classifier` (`docs/t033-evidence/size_composition.json`, C3 `non_encoder_head_keys`). The conclusion ("T-033 size target unaffected") is correct; the number should be corrected.
- [MINOR] **"Only this one field is projected" understates the mapping.** §7.1 and notes item 2 say `requestedApp` is the only non-verbatim value, but `callType` is also a closed-vocabulary projection and is marked (b) in the design's own table. Both are justified; the wording should say "the only span→field projection besides `callType`".
- [MINOR] **Loose line citations (substance holds).** `MethodResolver` "returns nil (`MethodResolver.swift:88-90`)" — the actual nil return is `:92-94`; "`speak(key:)`, e.g. `:2204`" — `:2204` is `speak(text: L10n.fmt(...))`; `T-034 §4.3 step 2` cited for first-subword tagging (step 2 is the word-tag rule; the subword projection is step 5); §3.3 "`return_offsets_mapping` not required" diverges from T-034 step 3 but is a named, invariant-preserving divergence.
- [MINOR] **Requirement traceability gap.** FR-008 (intent classification/entity extraction — this component's own requirement) is not cited anywhere in the design or contract; NFR-002 appears only in the amendment's adjacent-text note. One line in §1 mapping FR-007/FR-008/NFR-002 would close it.
- [MINOR] **`gates.measured_today` can be misread.** It lists `closed_intent_accuracy`, `slot_f1`, `emergency_recall_corpus`, whose only measurements are T-033's on the 20-row legacy corpus (0.882 / 0.333 / 1.000 — two below their gates). The design doc is honest (R-6, §15), but the machine-readable key should be qualified (e.g. "T-033 proxy on legacy 20-row corpus; not a gate pass").
- [MINOR] **Encoder timeout/retry not specified as configurable.** F-1 detects "forward pass exceeds the local-leg budget" but neither design nor contract pins the value or makes it a `Config` parameter with a stated retry policy, unlike `LocalIntentInterpreter.Config` (`timeoutSeconds: 10`, one retry). The review checklist requires configurable timeouts/retry limits, and the contract is what T-036/T-037 implement against.
- [MINOR] **Amendment class list order vs logit-order contract.** §4.2.3 lists the twelve classes in Swift-enum declaration order (`query` before `send_message`), while the contract/T-034 logit order has `send_message`/`guide` earlier and `query` eleventh; the next bullet says class order "is a contract". Add the canonical order to avoid ambiguity.
