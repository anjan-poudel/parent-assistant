## Decisions made during implementation

- **The addendum adds a layer, it does not repeal a decision.** The merged TG-12 design says twice, unambiguously, that this layer must not exist — D-2 (`:41`) bans fuzzy matching outright and §5 (`:448`, `:451`) states there is *"no edit-distance, no fuzzy match, no dictionary nearest-neighbour"*. Those sentences are about the **canonicalizer** and they remain true of it; the corrector is a different layer with a different evidence base (measured decoder errors vs attested dialect variants). §1.3 draws the boundary as a table and §1.3's closing paragraph states the important part: **the reason fuzzy matching was banned does not disappear, it transfers and it is harder here.** D-2's motivating hazard is `NepaliTextNormalizer` folding `माइया`/`maiya`, where *"maiya" and "maya" (different people)* become one key. A corrector that fuzzy-corrects a `contact` token can call the wrong person — which is why the entity veto and the prefix-only rule are structural parts of this design and not heuristics.
- **The measurement is the first task, and the design makes it the threshold's source as well as the lexicon's.** The brief asked for the error distribution to come first, from the existing piper→whisper round-trip pairs. The consolidated directive then required the confidence threshold's **default to be data-derived**. Both land in the same place: §4's extraction run produces the class frequencies, the phonetic key with its collision rate, the top-K word lists **and the false-positive population** — and §5.5.1's calibration is a precision/recall sweep over that set, with the shipped default at `argmax recall s.t. precision ≥ 0.95`. The threshold is written into the lexicon manifest **with the run id that produced it** and loaded as data; it is not a Swift literal. A stale calibration (a newer lexicon, or T-066's wider noise source) is refused at load.
- **The threshold's range is bounded by the invariant, not by taste.** The card lets a debugger raise the threshold freely and lower it only as far as the **C-2-derived bound** — the loosest value at which the never-flips-intent gate still holds on the corrupted slice. The calibration run emits that bound; the control is clamped to it and a test asserts the clamp. A threshold is an operating point; the invariant bounds the operating point. This is the sharpest reading of *"the never-flips-intent gate is the absolute floor regardless of threshold"* and it is enforced structurally rather than by convention.
- **Phase 1 is the MVP and the design keeps it genuinely independent.** Phase 1 applies corrections, logs every decision with a closed-vocabulary reason, puts a "Last correction" line on the internal testing card, emits count-only observability events, and passes a non-compelling correction note into the escalation context. **No brain behaviour depends on the signal** — and that is made checkable rather than asserted: C-7c is a structural test that the Phase-1 diff introduces no read of the correction result outside the input path and the two observability surfaces, with a planted violation (a `lowerConfidenceBy(0.1)` on the empty-applications branch) as the negative arm. Phase 2(a)'s routing discount is literally that line, which is why the check must be able to see it.
- **"The encoder's input and routing stay untouched" needed disambiguation, and the addendum says so in the design rather than the notes.** The corrected **transcript** *is* the encoder's input — that is the layer's whole purpose — so A-14 states precisely what is forbidden: correction **metadata** never enters the encoder's input (it would break the tokenizer and the span contract, and the encoder input has no prompt to carry it) and no correction **signal** enters the routing decision (Phase 2(a) is the only thing that would, behind a flag and a measured gate). The companion decision A-15 is what keeps the corrected transcript from breaking the encoder's training identity: the correction is a transform on a model's input, so the round-trip pass must be corrected with the **same shipped corrector revision**, and the corrected bucket must still retain a measured residual corruption (C-10b, ≥ 55 %, the existing `hard_floor_stt_noised`) or the encoder loses the robustness the 60 % bucket exists to train.
- **A third A/B arm was added, because one of the directive's Phase-2 statistics cannot be measured without it.** The arms are `.off` / `.shadow` / `.apply`. `.shadow` generates candidates and logs decisions while applying nothing — it changes no behaviour while it measures, so it is the clean source for `Δ_esc = P(escalation-worthy | ≥1 correction applied) − P(escalation-worthy | 0 applied)` in Phase 1. A-13 requires `.apply` as the shipping default; open question 6 records the sequencing question (shadow for an evidence window first?) as a design decision to take before T-076 wires the default.
- **The "Last correction" line follows the "Last turn" precedent exactly, including its privacy posture.** It is the same `Divider` + `ForEach(readout)` + monospaced label/value shape, in the same encoder card, in-memory on the coordinator, last-turn only, **never persisted, never logged** (`SettingsView.swift:3461-3494`). It shows the correction pair because that is the surface's entire diagnostic value on the user's own device. The egressing artifact is the separate **count-only, binned** observability event (A-16), because a raw score in telemetry is a fingerprint of an utterance shape. The diagnostic *tokens* stay unlocalized for the same reason the timing rows do — the card's vocabulary must match the device logs it is read against.
- **The escalation note is designed, gated, and has a specified zero-token fallback.** The directive requires the signal to be in the 4B's context from day one. The design honours it and states its cost precisely, because this is the one place Phase 1 touches a **fine-tuned artifact's input**: the picker prompt measures 696 qwen3 / 677 gemma tokens against a 1,024-token window (~300 headroom), a previous revision at 2,361 tokens returned EMPTY completions, and a **53-token trim** took emergency recognition from 5/7 to 0/7 draws on the base model. C-8 therefore gates the note on four checks — re-measure on the real tokenizers, re-pin `IntentPromptTests`' ceiling, confirm the utterance headroom, re-run the emergency draw check — plus the four-renderer same-change rule (`IntentPrompt.build`, `seeds/prompt_template.txt`, `intent_prompt.py`'s `PLACEHOLDERS`, both eval backends). If they cannot all hold, the note ships on the card and in the log only, and Phase 1 still works. **The note is not shipped at the cost of a safety number.**
- **The composed-transform gate-coverage hole is the addendum's most load-bearing finding.** With the corrector upstream of the canonicalizer, TG-12 §4.7's T-077 two-clause equality is defined over `(original, canonical)` while the transform the pipeline actually applies is now `(original, correct ∘ canonical)`. Left unamended, T-077 would keep passing while the new layer sits upstream of the transform it verifies. §7 C-4 re-scopes the gate onto the composition, extends the fixture with the corrector's own frozen material (the negation markers' **fragments**), and adds a second negative arm — `नखा` → `नखाए`, a plausible prefix completion that **manufactures a medication acknowledgement from a fragment of one** — which is the arm that proves the new layer is inside the gate rather than beside it. This is recorded as a gate-coverage hole, not a test addition.
- **No new task IDs, and the two near-misses are stated rather than buried.** §9 walks every piece of the design to the task whose stated scope already contains the seam, and records two places where a new ID could be argued: C-2b (the model-level intent-stability arm, which **cannot run today** and is recorded as gap G-A2 with T-078 as owner — a task that cannot be started is a gap, not a task) and Phase 2's two consumers (which are not being built now, so the proof obligation lives in T-078; the activation record is named as the trigger to allocate real IDs outside the group if Phase 2 is ever activated). Two estimates move and are recorded: **T-070 `S → M`**, **T-075/T-076 `L`/`M → L+`/`M+`**. Nothing is renumbered.
- **Phase 2's activation conditions are numeric comparators, never prose.** Each consumer has four conditions with row counts and confidence intervals: (a) `Δ_esc ≥ 5 pp` at `N ≥ 2 000` corrected turns with the 95 % CI excluding zero; a measured over-confidence gap `≥ 0.05`; `≥ +1 pp` on the discount's own A/B; no-regression arms at `≥ −0.5 pp` and emergency recall unchanged at 1.00. (b) `≥ +2 pp` at `N ≥ 500` escalated turns; `≤ +20 ms` p95; C-8 re-checked; emergency recall identical with and without the note. C-11 requires an **activation record** — the log window, the row counts, the measured values and an explicit ACTIVATE/DEFER/ABANDON — and enabling a Phase-2 flag without one is **refused** (exit 3), not warned about. b1's honest expectation of `+0` is written as a legitimate printable outcome.
- **House evidence discipline was made mechanical again.** Every gate in §7 carries a named fixture, a revision binding, an exit code from the existing vocabulary (`pipeline_guards.py:33-38`), and a **negative arm proving it can fail**. Every threshold is measured or labelled **chosen** (A-9) — and the chosen ones are open questions, not findings. Every entry in the correction lexicon carries a `evidence` block with a run revision and `occurrences ≥ 1`, enforced by an `issues()` validator that refuses the file, so an unsourced entry **cannot be written**. The `identityLeak` validator is new to the family: the canonicalizer's entry ids encode surfaces (`eastern-perfective-ichha`) and that is fine for public language, but a correction entry's surface is the user's utterance, so an id containing either surface refuses the lexicon.
- **Nothing was silently resolved.** The gap register has twelve entries, each naming what would close it and who owns it, and two of them are structural: **G-A5** (the corrector is calibrated *and* gated on synthetic round-trip noise — the same class of error as training and evaluating on one split, printed with every result) and **G-A1/G-A4** (the round-trip profile is one Hindi piper voice through one Whisper fine-tune, inheriting TG-11's GAP-1/GAP-2/GAP-3 unchanged).

## Corrections and findings recorded in the design

- **An offset-unit error in the merged design, load-bearing for this layer.** TG-12 §4.2 declares `CanonicalVariantApplication.originalRange/canonicalRange` to be *"Half-open **UTF-16**-offset ranges, matching the contract the encoder's span decoder already uses (`annotation_rules.yaml:96-104`)"*. The cited block says the opposite — `slots.offsets.unit: unicode_scalar`, with a note that UTF-16 offsets *"are wrong for Devanagari clusters — a known regression class for this project"* — and the shipped runtime agrees with the contract (`IntentEncoderInterpreter.swift:818-841`, `:41-57`). The addendum defines the corrector's map in **Unicode scalars** and assigns the doc-comment fix to T-072. This is not pedantry here: the corrector's entire job is changing string length, so an off-by-a-cluster unit error in its map is a wrong-span bug, and a wrong `contact` span is a wrong phone call.
- **A stale configuration claim.** Statements of "the round trip produces 6 variants" are wrong: `config.yaml:28` says `variants_per_utterance: 2`, and 6 is the round-1 LLM path's number (`2026-09-15-round2-quality-campaign-plan.md:391-392`). T-066 is the task that raises it. The addendum requires the value to be read from config at run time, and binds the extraction and the calibration to a re-run when it changes (G-A3, C-9c).
- **A vocabulary collision, recorded before it could bite.** The round-2 campaign's `confusion_pair` classes (`cp1a`…`cp5b`) are **intent** confusions (`create_calendar_event~set_reminder`, `guide~query`, `health_query~emergency`). This addendum's subject is **STT error classes**. The two must not share a word in an artifact, gate name or fixture name, or a future reader will read the intent-confusion report as the error distribution. The addendum uses **error class** for its own concept and reserves *confusion pair* for the round-2 sense.
- **A finding that changes the design's central mechanism.** The worked example is **ambiguous under the strongest naive rule**: `मौस` has two corpus continuations, `मौसम` and `मौसमको` (57 of the 121 prefix-related corpus tokens have ≥ 2 continuations; 64 have exactly one). A unique-continuation rule would refuse the user's own example. The paired-keyword prior is therefore not a refinement — it is the mechanism that resolves the motivating case, and the margin rule (A-5) is what protects the cases where it cannot.
- **A finding that weakens the prior and is stated anyway.** `भोलि`+`मौसम` co-occurs in exactly **1** row of the 8 000-row golden corpus. A raw pair-MI table would be zero or over-fitted, so the prior is a three-level backoff (pair MI → frame affinity → intent-conditional unigram) with per-level coverage reported. The level that actually resolves the worked example is **L2**: the frame `time-word + <truncated> + कस्तो हुन्छ` is attested 14 times with `मौसम` and 0 times with `मौसमको`, which occurs only before `समाचार`. That is a corpus measurement selecting the answer, not a convenience — and gap G-A6 records that both corpora are template-generated, so the prior is partly a description of the generator. Open question 1 makes "the prior measures +0, ship the prefix and fuzzy tiers alone" a printable outcome.
- **A measured correction to the framing of the whole layer.** 43 % of golden-corpus rows carry **no span at all** (3 437 of 8 000), and the worked example is one of them. Correction is riskiest where it touches a side-effecting span and cheapest where it does not; the corpus says the cheap case is nearly half the traffic. This is why §5.7's prefix-only rule inside required spans is affordable, and why the design does not compromise on it.
- **A cost the directive's Phase-1 requirement implies and the design states rather than hides.** Adding the `{corrections}` placeholder is a **four-renderer** change (Swift template, the seed the fine-tune tokenizes raw, `intent_prompt.py`'s `PLACEHOLDERS`, both eval backends), and it happens inside a 1,024-token budget with a documented EMPTY-completion overflow and a documented emergency-recognition cliff. The token cost is the smaller half of the real cost; C-8 gates the larger half.
- **A schema change with a precedent, justified rather than assumed.** The `stt_correction` `TurnTimingStage` opens a deliberately closed, `CaseIterable` set (`TurnTimingBreakdown.swift:45-47`), and everything enumerating it moves with it. `cascade_decision` is the precedent that justifies it (`:61-67`); folding the corrector's time into `encoder_tokenizer` is rejected because it would make one number mean two things.

## Open questions (carried into the task files, not silently resolved)

- **OQ-1** — does the paired-keyword prior earn its complexity? The worked example's exact pair occurs once in 8 000 rows and L2 (frame affinity) is what resolves it. If L1 contributes nothing beyond L2/L3, the honest design is a two-level backoff. **The prior must be ablated, not assumed**, and the ablation is a gate row.
- **OQ-2** — where does the precision/recall knee actually fall, and is the 0.95 precision floor the binding constraint or is the knee? §5.5.1 reports both so the answer is visible; if the floor binds, the corrector is precision-limited and better lexical evidence — not a different threshold — is what would help. This is the empirical core of the calibrated-default requirement.
- **OQ-3** — what is the L1 co-occurrence count floor? A pair seen twice is not evidence; one seen twenty times may be a template artifact. Chosen, unresolved.
- **OQ-4** — does the correction help the encoder **at all**, or only the pipeline's telemetry? The same honest prior as TG-12 OQ-1: a student trained on the noised bucket may already read `मौस` in context. C-2b is the measurement and it is unreachable today (G-A2, Stage 0 RED).
- **OQ-5** — does the prompt note measure positive or negative? The template's history says a small size change can move emergency recognition a long way in this exact model; it says nothing about whether a correctly-formatted correction field helps. D-20 measures it in Phase 1, b1 gates it in Phase 2, `+0` is printable.
- **OQ-6** — is `.shadow` the right Phase-1 default instead of `.apply`? The directive's MVP applies; the cleanest counterfactual for Phase 2(a) comes from `.shadow`. Running shadow for an evidence window and then switching collects both but delays the user-visible benefit. **A design decision required before T-076 wires the default.**
- **OQ-7** — should the corrector's lexicon be the clean corpus's 1 050-type vocabulary, or only the measured decoder errors? The vocabulary is the obvious source and an entry the decoder never produced is an entry authored from intuition. The tension is real; the resolution is a rule, not a preference.
- **OQ-8** — does the picker rung want any of this? The note is designed with a zero-token fallback unless C-8 passes. If typo-corrupted utterances are disproportionately the long tail, the argument inverts — the same possibility TG-12 OQ-5 records for the canonicalizer.
- **OQ-9** — is `prefixOnlyInRequiredSpans` too strict to buy anything? It is the safest rule and it will refuse some correct corrections. Measuring how often it refuses, on the rows where the correction mattered, is what would justify relaxing it — and relaxing it needs a safety argument, not an accuracy one.
- **Unresolved by design** — gap G-A9: whether a correction pair derived on-device is content under TG-10's hashed-egress contract remains referred to TG-10's T-053/T-059. A-11 restates it and T-079's Definition of done inherits TG-12's: it may not be settled by implementing an egress path.
