# Elderly AI Assistant — Deep Review & Productionisation Plan

**Date:** 2026-08-30
**Scope:** iOS (Swift), docs, requirements, build/repo hygiene
**Platform decision:** **iOS-first. Android support is deferred — no active Android work.** The `android/` tree is kept in-repo as reference scaffolding only. All findings and the roadmap below are iOS-only.
**Verdict:** Well-documented early scaffold, **not near-production**. Several safety-critical features are broken end-to-end or absent. Nothing is shippable today; gaps are structural, not polish.

---

## 1. Executive Summary

- Requirements/constitution/docs are excellent — genuinely well-specified.
- Code quality within individual files is thoughtful (escalation state machine, transcript sanity guard, log sanitiser design, checksum-verified model store).
- **But:** the core promise — medication reminders that escalate and alert family — currently only works while the app is in the foreground.
- Four patient-safety bugs found in the medication flow (false re-fires, shared escalation engine across doses, Nepali yes/no inversion, wedged confirmation state).
- Nepali TTS (the product's central promise) cannot work today: no Nepali voice on iOS, Piper runtime not linked.
- Health monitoring, emergency calling, authentication, and remote config are all absent (spec'd only).

---

## 2. What's Done Well

- **EscalationEngine** — clean, test-covered state machine; FR-027 off-by-one already found and fixed.
- **TranscriptSanityGuard** — pure, handles Devanagari hallucination modes (repetition loops, low entropy, absurd length).
- **ModelStore** — streaming SHA-256 verification, staging/final separation, `NSFileProtectionComplete` + iCloud backup exclusion done right.
- **LogSanitiser** — allow-list design (unknown keys dropped) is the right instinct.
- **Fail-closed auth** — call commands blocked because voice biometric auth isn't built yet. Honest, correct.
- **Honest docs** — plan docs acknowledge stubs rather than hiding them.

## 3. Critical Findings (C1–C14)

### C1. Medication escalation does not run in the background (iOS)
- `UNNotificationScheduler.scheduleAckDeadlineCheck` schedules a **user-visible silent notification** — it never executes `handleAckDeadlineExpired` in code.
- `AppCoordinator.registerBackgroundTasks()` registers a BGTask handler but **never submits a `BGAppRefreshTaskRequest`** (no `submit(` call anywhere).
- **Impact:** re-fire chain (FR-027) and missed-dose family alert (FR-028) only advance while the app is foregrounded.
- **Fix:** pre-schedule the full refire chain (0/12/24/36/48/60 min) as time-sensitive notifications; actually submit BGTasks; apply for the critical-alerts entitlement.

### C2. (Reserved — Android removed from scope)

### C3. Every app relaunch falsely fires all future reminders (patient-safety)
- `EscalationEngine.recover()` maps `.pending` → `start()` → fires **immediately** via `rearmAllPendingReminders()`.
- A `.pending` reminder is a *future* dose. Kill+reopen app at 15:00 → tonight's 20:00 reminder fires at 15:00.
- **Fix:** `.pending` recovery re-arms alarm for its `scheduledAt`, never fires early. Only `.fired` re-fires on relaunch (FR-029).

### C4. Twice-daily medications share one escalation engine
- `engines` keyed by `medicationEntryId`; two `scheduleTimes` per entry → second reminder **overwrites** the first's engine.
- 08:00 dose's escalation runs against 20:00 engine's `scheduledTime` → wrong ack/deadline math.
- **Fix:** key engines by `reminderId`.

### C5. "No" in Nepali is classified as "Yes" (patient-safety)
- `CommandRouter.isYesResponse` includes `"हो"`, checked **before** `isNoResponse`. `"होइन"` (no) contains `"हो"` (yes).
- Dementia user answering "होइन" to "did you take your medication?" is recorded as YES → dose logged → real dose skipped; double-dose protection defeated.
- English list has the same flaw ("not right" matches "right").
- **Fix:** token/exact matching, no-list checked first, regression tests with real Nepali negations.

### C6. Family alerts go nowhere — and the current design can't
- `APNsProvider.sendPush` is a print-and-return-true stub.
- "Elder's device pushes directly to family member's device token" is **architecturally impossible**: APNs sends require server-held credentials; you can't obtain a relative's device token without a backend.
- The repo's own `docs/remote-config-channel-design.md` specifies the right answer (Double-Ratchet broker relay; APNs only for wake-up).
- No retry/queue — one failed send = lost safety alert.
- **Until the broker exists, FR-028(a), FR-033(c), FR-035(b) are unmet.**

### C7. Health monitoring and emergency call are entirely absent
- Verified by grep: no HealthKit/Health Connect code, no `HKHealthStore`, no emergency dispatch module.
- FR-031–FR-037 (the "emergency safety net" from the constitution) = 0% implemented.

### C8. Authentication is absent
- No voice biometric enrolment, no PIN hashing (no bcrypt/Argon2), no biometric APIs anywhere.
- FR-011–015 unimplemented. Router fails closed (good) — but this is MVP-scope work that doesn't exist.

### C9. PII leaks despite the sanitiser
- `LlamaCommandInterpreter` logs a **160-char raw LLM output preview** into `metadata["state"]` — an *allowed key*, so transcript-derived PII flows to logs.
- `CommandRouter.postDebugNotification` posts **raw transcripts to user-visible lock-screen notifications**.
- `print()` calls with device-token prefixes bypass the bus entirely.
- All violate NFR-016.

### C10. Nepali TTS currently cannot work
- iOS has no Nepali `AVSpeechSynthesisVoice`; falls back to en-US reading Devanagari as gibberish.
- Piper Nepali voice is in the catalog, but sherpa-onnx runtime is not linked.
- **This is the product's core promise (FR-002/FR-006) — must be P0.**

### C11. Flagship Nepali Whisper model is a placeholder
- Catalog points at `huggingface.co/officialuser/whisper-large-v3-nepali-ggml` — `officialuser` is a placeholder org; model doesn't exist.
- `minDeviceRAMBytes: 7GB` → `MemoryProbe` rejects it on the iPhone 12 reference device anyway.
- Real Nepali STT today = stock `whisper-small-q5_1` multilingual (mediocre for Nepali per the repo's own gibberish-fix doc).

### C12. Confirmation flow can wedge the assistant permanently
- `pendingConfirmationEntryId` cleared only when a yes/no response arrives — **no timeout**.
- If the user walks away after a challenge, every future utterance is treated as a confirmation answer forever.
- **Fix:** timeout that clears pending state and re-enters escalation.

### C13. Spec/governance drift: constitution says React Native, code is native iOS
- Constitution: "RESOLVED: React Native (single codebase for iOS + Android)". Reality: native Swift (with a dormant Android scaffold, now deferred).
- With Android deferred, the practical resolution is to **amend the constitution** to state: native iOS for the MVP; Android re-evaluated post-MVP (native Kotlin reuse of the existing scaffold, or React Native/CMP rewrite). Keeping "React Native" as a resolved decision that nothing implements will keep misleading design work.

### C14. Keychain is being used as a database (iOS)
- Adherence log (unbounded array, rewritten in full on every event) lives in the Keychain.
- `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` → reminder state **unreadable while device locked** (e.g. after reboot before first unlock — exactly when med reminders matter).
- **Fix:** logs/reminders → file/SQLite with `NSFileProtectionComplete`; Keychain for keys/tokens only.

## 4. High Findings (H1–H11)

- **H1. Voice pipeline threading:** `@Published state` mutated from audio tap queue, main queue, and `asyncAfter` — data races + SwiftUI background-publish crashes. Make pipeline an actor or single serial queue.
- **H2. GBNF grammar is dead code:** never passed to inference (only referenced in a test). "Always well-formed JSON" claim is not enforced. `maxTokens`/`temperature` unused. **No timeout on LLM inference** → hung model hangs routing forever.
- **H3. Prompt injection:** raw transcript interpolated into prompt; constitution's `quarantine`-level injection detection (NFR-013) not implemented.
- **H4. False-positive medication acks:** keyword list includes `"done"`, `"भयो"`, `"खाए"` matched by substring — casual conversation acks a dose.
- **H5. Audio interruption doesn't resume engine:** after a phone call, session reactivates but `AVAudioEngine`/tap never restarts → wake-word loop silently dead. `try?` swallows failures.
- **H6. VAD too aggressive for elderly speech:** `endOfUtteranceMs: 200` clips slow speakers mid-sentence. Target 700–1000ms, configurable.
- **H7. First-command latency spike:** Whisper loads lazily on first inference (+ ANE compile 10–30s). NFR-001 (2s) unmet on first use. Preload at launch / post-download.
- **H8. PhotoVerifier corrupts images:** `compressIfNeeded` truncates raw bytes → undecodable JPEGs. Use real UIImage/Bitmap compression.
- **H9. ModelDownloadService:** leaks a session+task; `maxConcurrentOperationCount` set on wrong session; no download resume; no background URLSession (needed for 3GB models on flaky Wi-Fi).
- **H10. Cert pinning:** no APNs-relay domain provisioned yet — pinning to be added when the broker relay server exists.

## 5. Medium / Low Findings

- **Localization absent:** hardcoded strings everywhere (English notifications, English challenge prompts spoken to Nepali users). Violates NFR-023/024. Need String Catalogs (`.xcstrings`) with ne + en.
- **Accessibility NFRs violated by own UI:** caption fonts (<18pt, NFR-021), small talk button, English-only, no high-contrast mode.
- **No onboarding, no settings, no privacy policy screen (NFR-032), no in-app config (FR-042).**
- **iOS packaging:** no `PrivacyInfo.xcprivacy` (required by Apple), no `ITSAppUsesNonExemptEncryption`, Light-only UI, `fatalError` on ModelStore init, force-unwrap in VoicePipeline, non-idempotent `start()`.
- **UN notification 64-request ceiling** — refire chains + ack checks across meds can hit it.
- **SPM packages pinned to branches** (`master`/`main`); `LLM.swift` is a personal repo — reproducibility + supply-chain risk.
- **CoreML encoder triple-broken:** Resources/ untracked, `*.mlmodelc` gitignored, `project.yml` has `resources: []` → encoder can never be bundled; `installBundledCoreMLEncoder` always no-ops.
- **Repo hygiene:** generated `project.pbxproj` tracked while `project.yml` is source-of-truth (pick one); `ios.bak/` should be deleted; `android/` should be clearly marked dormant (or moved out of active build paths); 2-commit history with WIP mega-commit; no root README; no CI; no `.env.example`.
- **No eviction/retention policy** for adherence log; photo 1-hour deletion (FR-D04b) is a comment, not code; no timezone/DST strategy.

## 7. Productionisation Roadmap

### Phase 0 — Stop the bleeding: safety correctness (1–2 weeks)
1. Fix **C3** (pending-vs-fired recovery), **C4** (engine keyed by reminderId), **C5** (Nepali negation tokenization + regression tests), **C12** (confirmation timeout).
2. Add kill-and-relaunch + multi-dose integration tests (NFR-027) — these four bugs are exactly the class the spec predicted.
3. Remove all PII leaks (**C9**) — precondition for any TestFlight release with real users.

### Phase 1 — Reminders that work when the app is closed (2–3 weeks)
4. Pre-schedule the visible refire chain as time-sensitive notifications; submit real BGTaskRequests; apply for the critical-alerts entitlement; move reminder/log storage to file-based `NSFileProtectionComplete`.

### Phase 2 — Alerts & remote config (3–5 weeks)
5. Stand up the broker relay per `docs/remote-config-channel-design.md` (unblocks family alerts, remote config, companion app). Interim option: trusted relay + server-side APNs sender. Durable queue + retry for alerts.

### Phase 3 — Voice quality for the real user (4+ weeks, parallel)
6. Nepali TTS via Piper + sherpa-onnx (**P0 — it IS the product**). Preload models; VAD to ~800ms; properly bundle + wire CoreML encoder; train/quantize/host the Nepali Whisper fine-tune to fit <2GB; enforce GBNF or drop the claim; add LLM timeout.
7. Reassess wake word: Porcupine lacks Nepali — evaluate Sherpa-ONNX KWS or custom KWS per research doc.

### Phase 4 — Missing MVP features (4–6 weeks)
8. Voice biometric enrolment/verification + Argon2 PIN + re-enrolment flow (FR-011–015).
9. HealthKit monitoring, hardened emergency-call module (isolated, no LLM dependency), fail-safe alerts (FR-031–037).
10. Onboarding (language, voice enrolment, emergency number per OD-009), in-app config behind auth (FR-042), Messenger deep links (FR-016–020).

### Phase 5 — Ship-readiness
11. Localization infrastructure (String Catalogs, ne + en), elderly-UI pass (44pt targets, 18pt+, contrast), privacy policy + privacy manifest + App Store health-data declarations.
12. STRIDE signoff against implemented reality, injection-sanitisation layer (NFR-013), CI (build+test on PR), pin dependencies, crash reporting sans PII.
13. Beta with 5–10 real families before calling anything "24/7 safety-critical".

### Deferred — Android (post-MVP)
- Keep `android/` untouched as reference scaffolding. Do not invest in fixes (POST_NOTIFICATIONS, receiver wiring, security-crypto dep, FCM setup) until Android is re-scoped.
- When Android returns: re-validate against this document — every iOS-fixed bug class (C3/C4/C5-style) likely has a mirrored Android instance in the scaffold.

---

## 8. Meta-Recommendation

Spec claims 100% unit test coverage on safety-critical paths (NFR-026), but C3–C5 sailed through because tests exercise the engine in isolation, not scheduler+recovery+router wiring. **Add integration tests for kill/relaunch mid-escalation and multi-dose-day scenarios before Phase 1**, and make invariants like "engines keyed per-reminder" testable.
