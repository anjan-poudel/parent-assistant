### 4.2 Intent + Slot Encoder

A single on-device **joint encoder** maps one transcribed utterance to one schema-v2
action and a set of **verbatim text spans** that name the slots. It is not a
prompt-engineering layer and not a separate model process: it is a local, quantized
neural artifact loaded at runtime and exposed to the router through the same protocol
every other interpreter implements.

Two properties are architecture, not implementation detail:

1. **Spans in, resolution in code.** The encoder emits substrings of the transcript it
   consumed. It never emits a contact id, phone number, URL or resolved clock time.
   Turning a span into a target is deterministic Swift (§4.2.4).
2. **It proposes; it never executes.** No encoder output reaches a side-effecting
   action except through the confirmation tiers in §4.2.5.

#### 4.2.1 Component and runtime format

| Element | Choice |
|---|---|
| Body | 12-layer MiniLM (XLM-R sentencepiece tokenizer, 250 037 vocab), ~117 M params |
| Heads | intent head `Linear(384, 12)` over the pooled `[CLS]`; BIO slot head `Linear(384, 13)` over every token |
| iOS artifact | CoreML `mlprogram`, int8 weights, distributed as a zip containing one `<stem>-encoder.mlmodelc` |
| Android artifact | ONNX, int8, opset 17, run through ONNX Runtime Mobile |
| Graph signature | inputs `input_ids` + `attention_mask` (int64); outputs `logits` + `slot_logits` (**raw**, unnormalized) |
| Metadata | an adjacent `meta.json`: ordered intent list, ordered tag list, `max_len`, `calibration_temperature`, artifact digest |
| Size | int8 ≈ 109–118 MB (CoreML zip / ONNX) |

The encoder runs **fully on-device** (FR-007). Network is never required for it.

#### 4.2.2 Interface — `CommandInterpreter` conformance

The encoder is a `CommandInterpreter`
(`Services/Voice/LlamaCommandInterpreter.swift:34-41`) and additionally reports
failures:

```swift
final class IntentEncoderInterpreter: CommandInterpreter, InterpreterFailureReporting {
    /// True when the artifact is installed and its graph loads.
    var isAvailable: Bool { get }

    /// Non-nil only for real failures ("inference_timeout", "span_invalid", …).
    /// An abstention leaves this nil — abstention is not a failure.
    var lastInferenceFailureReason: String? { get }

    /// Always calls `completion` exactly once, on the main queue.
    func interpret(transcript: String,
                   context: InterpreterContext,
                   completion: @escaping (InterpretedCommand?) -> Void)
}
```

Contract:

- Input is `InputSanitiser.sanitise(transcript, level: .quarantine)`; if the sanitised
  string is empty, `completion(nil)`.
- **Span offsets are into the sanitised string**, because the sanitiser rewrites the
  text it is given (`Services/Voice/InputSanitiser.swift:42-73`).
- `completion(nil)` means **abstention**, and is distinct from
  `lastInferenceFailureReason != nil`, which means **failure**. The router reads them
  differently: an abstention is an open question, a failure is `local_failed_fallback`
  (`Services/Intents/IntentRouter.swift:211-219`).
- `InterpreterContext` is accepted for protocol conformance and is not consumed: the
  encoder's input is the transcript alone. Feeding it display-name data would create a
  train/inference skew.
- `completion` fires exactly once on every path, including timeout and every error
  branch.
- The component introduces **no new threshold** and **no new routing decision**. Bands
  (§4.2.5) and tiers are the router's and the confirmation flow's.

#### 4.2.3 Output vocabulary — schema v2, and nothing else

The intent head's classes are exactly the twelve schema-v2 action values
(`Services/Voice/LlamaCommandInterpreter.swift:66-88`), in the canonical logit order
below — which is **not** the Swift enum's declaration order, and **not** an
implementation detail:

```
index  0        1       2          3              4             5
       ack_med  call    emergency  set_reminder   health_query  music

index  6             7       8                      9              10     11
       send_message   guide   create_calendar_event  suggest_video  query  none
```

- Class index *i* is `meta.json: intents[i]`. This order is a contract: reordering it
  silently changes every prediction, so a reorder requires retraining, not a metadata
  edit. The order is the one `annotation_rules.yaml` `taxonomy.labels` defines, and
  T-036 asserts the two element-wise at build time.
- The runtime-only `plugin` case is **not** a class. The encoder cannot emit `.plugin`;
  plugin dispatch is a separate runtime path.
- The `CALL_CONTACT` / `QUERY_CALENDAR` / `SET_REMINDER` / `HEALTH_QUERY` /
  `GENERAL_CONVERSATION` names of the previous revision are **withdrawn**. No
  `SCREAMING_SNAKE` intent name exists anywhere in the schema.

The slot head's tags are `O` plus `B-`/`I-` for six span labels — `contact`, `time`,
`medication`, `message`, `topic`, `app` — **13 tags**, no BILUO, in that order:
`O`, `B-contact`, `I-contact`, `B-time`, `I-time`, `B-medication`, `I-medication`,
`B-message`, `I-message`, `B-topic`, `I-topic`, `B-app`, `I-app`. Tag index *j* is
`meta.json: tags[j]`, under the same contract.

#### 4.2.4 Slot contract — spans, not resolved values

Every slot in `InterpretedCommand` is either a verbatim substring of the sanitised
transcript or a closed-vocabulary projection of one:

| `InterpretedCommand` field | Origin |
|---|---|
| `contact`, `time`, `medication`, `message`, `topic` | verbatim span; `contact` may have a trailing dative/accusative clitic trimmed (`लाई`/`ले`/`मा`/`बाट`/`को`/`का`/`की`), applied to the `contact` label only and only when the remainder is non-empty |
| `requestedApp` | canonical token from a closed app vocabulary (`whatsapp`, `facetime`, `messenger`, `viber`; Devanagari forms by containment), **else nil** — the user must have *named* an app |
| `callType` | `"voice"` or `"video"` when the span is a generic method word (`phone`/`फोन`/`call`/`कल`, `video`/`भिडियो`), else nil |
| `action`, `confidence` | the intent head's argmax and its calibrated probability |
| `entryId`, `steps`, `reply`, `pluginAction`, `pluginEntities` | **not from the encoder** — later layers, code templates, or the LLM long-tail path |

`requestedApp` and `callType` are a deterministic split of the single `app` span,
reusing the shipped vocabulary (`Services/Intents/CallLinks.swift:248-251`, `:257`;
`Services/Intents/MethodResolver.swift:87-113`). `steps` and `reply` are free text and
therefore structurally outside any classification head: `steps` comes from a
deterministic runbook template or the LLM, `reply` from the LLM for Reply-class actions
or a template otherwise. **No free text is ever generated by the encoder.**

Resolution stays in code, unchanged:

| Span | Resolver |
|---|---|
| `contact` | `ContactResolver.resolve(_:)` |
| `app` → call method | `MethodResolver.resolve(contactId:requestedApp:callType:)` |
| `time` | `NepaliTimeParser.parse(_:)` |

#### 4.2.5 Confidence bands and confirmation

The encoder emits the calibrated confidence defined in §4.2.6 and hands it to the
existing band policy. **No component of this design defines its own threshold.**

| Calibrated confidence | Outcome |
|---|---|
| `≥ 0.7` | accepted |
| `0.4 – 0.7` | dispatched into the ordinary confirmation flow for tier-`confirm` actions (`call`, `send_message`, `set_reminder`, `create_calendar_event`); for tier-`free` actions, dropped for escalation or returned as the "did you mean…" rephrase question when the local brain is final |
| `< 0.4` | **abstention** — `completion(nil)`, no failure reason |

Bands are `IntentRouter.Config.default` (`acceptThreshold 0.7`,
`rephraseThreshold 0.4`, `Services/Intents/IntentRouter.swift:56-58`) applied by
`bandChecked` (`:316-330`). Confirmation tiers are
`Services/Intents/ConfirmationTier.swift:17-34`. The cache never skips confirmation
(`Services/Intents/IntentCommandCache.swift:10-13`) and caches only `call`, `music`,
`suggest_video` (`:51-65`) — `emergency` and `ack_med` are never cacheable, so no
abstention can be laundered through the cache.

#### 4.2.6 Calibration

Confidence is a **calibrated** scalar, not a raw softmax. A single temperature `T` is
fitted on a held-out split after training and shipped as `calibration_temperature` in
`meta.json`; the interpreter applies `logits / T` then softmax. The graph deliberately
outputs raw logits so the parameter is reviewable rather than compiled into the
artifact. Temperature scaling is monotone, so it cannot change the argmax — only the
confidence the bands read.

The ship gate is spec §10's bucketed calibration: over ten fixed buckets, every bucket
with ≥ 30 samples must satisfy `|accuracy − mean predicted confidence| ≤ 0.10`. Buckets
below the floor are pooled upward and reported as pooled.

#### 4.2.7 Position in the fail-soft ladder

```
keyword safety net → cache → local encoder → cloud brain → re-prompt
                                    ↘ (on abstention) incumbent local LLM (FR-007 long tail)
```

The keyword safety net runs **before any interpreter**, unconditionally
(`Services/Voice/CommandRouter.swift:645-653`): emergency and explicit medication
acknowledgement are matched there (`:1403-1408`, `:1454-1469`), and denial is checked
before ack because refusal words contain ack words as substrings (`:1443-1452`). A
low-confidence or abstaining encoder therefore **cannot** suppress an emergency or an
explicit med-ack — those utterances never reach it.

The encoder is installed as the preferred local brain with the LLM as stand-in
(`Services/Intents/LocalBrainChain.swift:28-69`); when the artifact is absent,
`isAvailable` is false and the incumbent answers unchanged. The LLM remains the
long-tail brain (§4.1) — this component is a **peer** of the incumbent local model, not
a replacement for the cloud fallback, and inference stays on-device (FR-007).

#### 4.2.8 Determinism and failure behaviour

The encoder has **no sampler**: one deterministic forward pass, then argmax. The
`OnDeviceSampling` policy (`temperature 0`, fixed seed) governs the LLM interpreters,
not this component — it does not apply because there is nothing to sample. Ties resolve
to the lowest class index; span decoding proceeds word-by-word in ascending order with
first-subword tagging. Same input, same device, same artifact digest ⇒ same action and
the same span set; confidence may differ in low-order decimals across CoreML/ONNX
kernels.

Failures, each with a fallback that cannot produce a wrong action:

| Failure | Behaviour |
|---|---|
| Inference timeout | failure reason set → router escalates to the cloud brain when configured |
| Artifact missing / corrupt / unloadable | `isAvailable == false` → stand-in local brain answers |
| Sanitised input empty | abstain |
| Decoded span invalid (fails `transcript[start:end] == text`, out of range, or overlapping another label) | drop the span; **abstain** if it was required for the action (contact for `call`/`send_message`, time for `set_reminder`) |
| Out-of-vocabulary utterance, including plugin requests | abstain at best; a confidently wrong closed action is caught downstream by tier-1 confirmation for every side-effecting action |

Observability events: `encoder.load_started`, `encoder.load_completed{durationMs,digest}`,
`encoder.infer_started`, `encoder.infer_completed{durationMs,action,confidence}`,
`encoder.abstained{top_confidence}`, `encoder.infer_timeout`, `encoder.span_invalid`,
`encoder.load_failed`. **No transcript content, no span text and no resolved value
appears in any event.**
